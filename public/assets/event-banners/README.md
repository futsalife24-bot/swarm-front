# SWARM FRONT 演出画像の読み込み仕様

2026-10-12。ClaudeCode原稿を元に制作した7イベント・標準/モバイルのAPNGと静止PNGです。この素材転送ではゲームコード、main、本番配信を変更していません。

## 配置
- standard/<event>.apng と standard/<event>.png: 960×336
- mobile/<event>.apng と mobile/<event>.png: 640×224
- consumer-manifest.json: このフォルダーを基準とする画像パス、時間、寸法、容量
- validation.json: 制作時の画像検証結果。ゲーム統合試験の結果ではありません

イベントIDは adv-sortie（進撃出撃）、adv-extract（進撃撤収完了）、adv-failed（進撃作戦失敗）、adv-complete（進撃作戦達成）、srv-sortie（生存出撃）、srv-extract（生存撤収完了）、srv-ended（生存戦闘終了）です。進撃と生存の同名イベントを区別してください。

## 読み込みと表示
1. 透過RGBAのAPNGは1回再生し、最終フレームは完全透明です。APNG非対応時の既定画像は完成状態です。
2. 幅100%、最大960px、aspect-ratio:960/336を保持します。モバイル版も同じ比率で、独立した文字レイアウトです。
3. 結果が確定してから該当イベントを表示します。画像や終了タイマーに保存・報酬確定を依存させません。
4. 画像レイヤーはpointer-events:none。戻る・再出撃・新イベント・非表示で即取消し、旧タイマーが新画面を削除しない世代管理を行います。
5. 回収はmanifestのdurationMsを使います。1980〜3040msの画像を1100msなどの固定タイマーで切らないでください。ロード失敗や遅延でも操作と保存は継続します。
6. prefers-reduced-motionまたは演出OFFではAPNGを取得せずPNGを使います。静止PNGは160msフェードイン→holdMs保持→160msフェードアウトを基準とし、動きOFFではフェードも省略できます。設定変更中もsrcを切り替えるか即取消してください。
7. 結果文字は通常DOMでも保持し、読み上げ通知は1回だけ。装飾画像はalt=""とします。実データ・ボタンは画像外に置きます。
8. 低性能端末ではmobile版を1枚だけ取得・デコードし、全14APNGを同時プリロードしません。実機メモリー測定は未実施です。
9. 戻る、再出撃、連打、画面切替、取消、画像エラー、reduce設定変更を組込み後に検証してください。音の変更は含みません。
