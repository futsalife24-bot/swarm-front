サーバー側の胴体中心の移動は、次のとおりです。
- 接地面・向き・壁への移行（凹んだ角と出っ張った縁）を計算する。
- 縁を越えるときは、胴体を縁に沿った曲線で動かす。
- 胴体の4点（頭・胸・外套・外套の先端）を、縁の前後の面の外側に保つ。これは計算だけで行い、レイは使わない。
- 膝の高さまでの段差は、壁として登らずに上がる。
- 胴体の追従ばねは残している。
- レイは1/30秒あたり最大4本。

端末側の足の演出は、次のとおりです。
- 足は対角の2本ずつ交互に踏み替える。
- 近景（カメラから24m未満）では、踏み出すときだけ地図へのレイで接地点を探す。
- 中景（48m未満）と遠景では、胴体の下の平面を歩かせる。骨の更新も間引く（中景30Hz、遠景15Hz）。
- 予備動作中と攻撃中は間引かない。
- 胴体の位置は毎フレーム更新する。
- 1回の計算で新しいオブジェクトを作らない。

攻撃・当たり判定・移動結果は、すべてサーバーで決まる。描画品質やカメラ距離で変わることはない。端末の足は `World` へ書き戻さない。

対象はPLEAT（内部名 `crawler`）だけです。ボスや他のANOMALYのコードは変更していません。モデル（`pleat_motion_v5.glb`、4,394,424B）も変えていません。

## 3. 速度を変えないための較正

旧方式は、足の制約によって指示速度より遅く進んでいた。平地を直進させ、dt=0.05で30秒の平均を測った（`scripts/calibrate-pleat-speed.test.ts`、`legacy-speed.json`）。製品の組み合わせで実際に出ていた速さは次のとおり。

| 個体 | 指示 | 旧の実効速度 |
| --- | --- | --- |
| size 0.8〜1.0（scale 1.2〜1.5） | 5.25 | 1.70〜2.77 m/s |
| 同上・突進 | 11.55 | 1.70〜2.25 m/s（通常時より遅いサイズがある） |
| size 1.05〜2（scale 1.575〜3） | 3.5 | 2.36〜3.50 m/s |
| 同上・突進 | 7.7 | 2.52〜4.26 m/s |

新方式はこの表を補間して使う。`tests/pleat-locomotion.test.ts` では、製品の全サイズで次の2点を確認している。
- 30秒平均の比率が、旧方式と3%以内で一致する。
- 静止から0.5m進むまでの時間が、旧方式と±0.1秒以内で一致する。

隊員の基本歩行速度は7 m/sなので、PLEATは最速でも約4.3 m/s。

**新旧の組み合わせ**

- 旧サーバーと新端末：新端末は `feet` を読まず、自分で足を置く。

**通信から外せる項目（96体の実際の戦況で試算。タプル形式ではない通常のJSON）**

| `feet` を外す | 14,678B | −69% |

- `body` は、敵本体の `x`、`y + 0.8×scale`、`z` と丸め誤差（0.005m）以内で一致した。

## 7. 難易度（今回は変更していない。別の変更として提案）

**今回の根拠**
- 基準測定の入力列（射撃せず円を歩くだけ）では、PLEAT 24〜96体を相手に20秒間、被弾が0だった。
- PLEATの実効速度は最大約4.3 m/s。突進は、小型では通常時より遅いこともある。
- 予備動作の0.8秒間は止まっている。攻撃が成立するのは2.5m未満。歩く隊員（7 m/s）は、この0.8秒で約5.6m離れる。

**提案（いずれも新しい変更として、計測しながら1つずつ）**
1. **接近速度：** `pleat-gait.ts` の表を基準に、速度係数を明示した設定として分ける。通常時は4.5〜5.5 m/s、突進は短時間で隊員より速い8 m/s前後を候補とし、突進前に予告を出す。サイズ差は残す。
2. **予告付きの踏み込み：** 予備動作の開始時に方向を固定し、地面に予告を表示する。攻撃時は、固定した方向へ3〜4m踏み込み、その経路上で当たりを判定する。真っすぐ逃げるだけでは避けられず、横へ動くか回避が必要になる。
3. **進路を塞ぐ：** 一部の個体は、隊員の速度から予測した数秒先の地点や、進行方向の左右を狙う。近い個体から順に処理しないと包まれる配置にする。

評価は、今回の基準測定と同じ「歩くだけの入力列」での被弾数、被弾までの時間、回避や方向転換を入れた入力列との差で行う。
