# グレネード射撃線の描画待ち：製品差分と再現テスト

## ファイル

- `src/client/combat-effects.ts` に修正を適用済み。
- `scripts/check-grenade-first-draw.mjs`: 適用済みの `CombatEffects` を隔離WebGLシーンで検査。
- `scripts/check-grenade-first-draw-live.mjs`: 844×390 の実ローカル単独プレイで GL-6・ST-3・RL-2・AR-9 の初回射撃を検査。
- `grenade-first-draw-lifecycle.json`・`grenade-first-draw-live.json`: 製品コード適用後の結果。

## 再現

```powershell
node scripts/check-grenade-first-draw.mjs
node scripts/check-grenade-first-draw-live.mjs
npm run typecheck
```

最初の２つはローカルサーバーとブラウザーが必要。引数なしで適用済み製品コードを検査する。

## 動作と検証結果

銃口があるグレネードの短い方向マーカーから生成された射撃線のみ、実描画を待つ。初回描画までは加齢と移動を止め、描画後は通常寿命へ戻す。描画されなければ100msのタイマーで回収する。描画後・回収時・clear時・再利用時にフックとタイマーを解除する。効果上限180は変えない。

正式コードでの隔離WebGL検査: 実描画後・非表示・画面外での回収と同一プール品再利用、180件満杯、残り１枠、100イベント／最大90本待機、clear５回／450タイマー、対象外ライフル・ロケットが合格。短い更新を複数回受けても描画までは位置・不透明度が変わらず、描画後は移動・減光した。残り１枠では既存の上限制約により射撃線が入り発光は追加されない。実ローカル画面ではGL-6・ST-3が初回に線の描画処理を通り、RL-2・AR-9も正常に描画された。画面例外0。

100msはイベントループが動いている場合のタイマー設定であり、厳密な経過時間の上限ではない。先行の隔離実測では非表示約125ms・画面外約114ms。ページのフリーズ、バックグラウンドでのタイマー制限、非常に長い同期処理ではさらに遅れる。描画コールバックは遮蔽なく画素が見えた証明ではない。先行画素対照では短い１フレームの差はGL-6で68画素、ST-3で31画素で、通常サイズでの視認性は未確認。

## 未確認

実画面の対象外確認はRL-2・AR-9のみ。多数人の実戦、継続射撃、通信、実スマホ、実機の描画負荷・音、凍結中の実際の回収時刻は未確認。90本待機は180件の上限の中で弾と発光が各１件生成される試験条件であり、すべての混在パターンやタイマー負荷を網羅しない。
