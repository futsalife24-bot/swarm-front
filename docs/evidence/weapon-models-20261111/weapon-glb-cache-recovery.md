# 新規武器GLBの不正キャッシュ回復

公開前の独立監査で指摘された、GLBのURLにSPAのHTMLがHTTP 200で返る場合を、隔離ローカルの実Service Workerとブラウザーで再現した。修正前はHTMLが通常キャッシュに保存され、配信元を正しいGLBに切り替えた後も同じHTMLを返した。[修正前の結果](weapon-glb-cache-before.json)。

`unique-v1/` のGLBに限り、PRELOAD・通常キャッシュ・ネットワークの順に、GLB v2のヘッダーと長さを確認した応答を使う。無効な保存済みデータは飛ばし、正常なデータが得られたときだけ該当箇所を置き換える。ネットワークからHTMLが返った場合は保存せず、失敗として扱う。既存のキャッシュ名や他のアセットの取得方法は変えない。

修正後の実ブラウザー確認では、HTMLと誤ったバイナリMIMEのHTMLを拒否し、配信元修正後は正常なGLBを取得した。PRELOADが不正でも正常な通常キャッシュから回復し、両方不正な場合も正常な配信元から復旧した。正常なPRELOAD・旧３武器のうちAR-9はオフラインで読め、キャッシュ済み・ネットワークの各Range取得も確認。503は保存せず、正常なキャッシュもないオフラインでは失敗する。ページ例外0。[修正後の結果](weapon-glb-cache-after.json)。

キャッシュ書込失敗は実ブラウザーでは再現できず、同じ製品SWをNodeの隔離モックで実行して確認した。オンラインで正常な応答を使え、書込に失敗したままオフラインになると不正な保存分を返さず失敗する。ヘッダー検査はHTML等を除外するもので、GLB内容の完全性や最新版を保証するものではない。実Worker・実スマホ・全武器の実画面は未確認。

再現は作業worktreeのルートで `node scripts/check-weapon-glb-cache.mjs`。修正前の再現には修正前の `public/sw.js` を用い `node scripts/check-weapon-glb-cache.mjs --baseline` を実行した。
