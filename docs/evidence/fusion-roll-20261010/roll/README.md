# 回避ローリングの比較証拠

基準 `f1298bb1632ce3844023a822fe495db6445227d1`、作業ブランチ `codex/fusion-roll-polish-20261010`。担当モデル `gpt-6.1-sol`、推論 `high`。主担当へ統合する前のローカル検証で、独立Chat監査・公開確認ではない。

兵士GLBは `d1028fd14cb42cfab2a0c484c57fa99032dc73609f8c3a08684abdec76f35269` のまま。素材の回避は1.467秒だが、回転は主に0.33〜0.84秒に集中している。以前は全1.467秒をゲームの0.32秒へ縮めたため、飛び込み後の回転が約0.11秒へ圧縮されていた。

変更後は回避の0.32秒で素材0.90秒までを使い、直立への復帰を描画の0.18秒へ分散する。横回避の下半身の軸は連続的に戻し、上半身の照準・両手・武器は現在の向きへ合わせる。回避の移動速度・時間・無敵・クールダウン・射撃と切替の制限・通信は変更していない。

`comparison-0.mp4`（ライフル）、`comparison-1.mp4`（散弾銃）、`comparison-2.mp4`（ロケット）は左が修正前、右が修正後、通常速度30fps。3秒の前方回避・復帰・射撃・横移動を並べた。後半1.7秒の回避入力は既存クールダウンに阻まれ、横移動のみになる。左回避は `left-comparison.mp4` の独立した1.5秒比較で補完する。`roll-contact.jpg` は前回避の姿勢推移の補助資料で、動画全体の評価の代わりではない。

実ゲームの `Renderer` と `step`、現行マップ・兵士・武器を使い、敵なし・影なしの独立した固定入力fixtureで各コマを描画した。640×360・30fpsへ固定して保存。描画がauthorityを変更しないことを毎コマ検査し、修正前後の世界時刻・回避残秒・弾数・座標が完全一致した。`browser-checks.json` と `left-browser-checks.json` に各コマの状態、描画の骨盤姿勢、製品ソースとGLBのSHAを保存。前回避中の骨盤最大角速度は3武器共通で50.82→29.80rad/s（約41%低下）。これは30fpsサンプルの回転差分で、物理の移動速度や端末性能の計測ではない。

自己検証: `tests/front-soldier-roll-motion.test.ts` の4件と既存 `tests/standard-trooper.test.ts` の4件が成功。描画によるPlayer変更なし、復帰中の射撃・移動・武器切替、新規回避・死亡・run境界での古い復帰軸の消去、横回避後の射撃軸を検査した。型検査成功。統合後のビルド・全体検証・独立監査・公開は主担当が記録する。

録画の最初の失敗は、比較用基準コピーの動的importパスが元の場所を指しており、Vite500で読み込めなかったことが原因。パス補正後に録画を新たに完遂した。準備中に影を使った960×540の試行と、描画のanimate引数を誤ってfalseにした試行は中断し、証拠には採用していない。最終録画は640×360・準備前から影無効・animate=true。ViteのHMR用WebSocketはローカル通信制限で失敗し、Viteクライアントの送信エラーもconsoleに残る。素材読込・ゲーム描画のpageerrorは空だが、console error 0とは報告しない。

再現:

```powershell
npm run dev -- --port 5344 --strictPort
node scripts/check-soldier-roll-polish.mjs
$env:ROLL_REVIEW_DIRECTION='left'
node scripts/check-soldier-roll-polish.mjs
Remove-Item Env:ROLL_REVIEW_DIRECTION
```

スクリプトは上記baseの `git show` から基準ソースを取得するため、手動コピーは不要。生成先は `dist-validation/roll-polish-20261010/` と同名の `-left/`。比較基準の描画クラスだけをブラウザ検証時に差し替え、製品ソース・保存データ・キャッシュ・進行データを変更しない。ffmpegは各出力のエンコードを2スレッドに限定する。

通常の操作入力・実端末FPS・スマホ実機・実通信協力・傾斜地形・公開配信はこのfixtureの対象外。連続動画では回転を見分けられる区間が増え、しゃがみから立つ区間が複数コマへ広がったことを確認できる。自然さの最終採否はユーザーと独立監査の判断を待つ。
