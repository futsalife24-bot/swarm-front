# 描画待ちと操作入力の採取を分離

2026-10-30、作業基点029d1ab、実装 `94b73469464d6bafc3865a49140792afdc0c8939`。先行の[入力窓とCPU診断](input-continuity.md)では、RAFが約500ms呼ばれない間にもWorld受信が動いていた。生存と進撃の実画面も入力をRAF内で採取していたため、描画の呼出し待ちが操作送信を止める。JavaScript全体が処理を止めた場合まで別のタイマーで解消できるとは扱わない。

## 実装

`NetworkInputLoop`を両Networkへ接続し、welcome受理後だけ50ms周期で最新入力を採取する。前回callbackの終了から50ms空け、停止時間分を一括送信しない。既存の20Hz送信上限・4096B送信buffer・受信時刻による4/16件のACK窓・サーバー250msの入力期限・35件/秒の受信制限は維持する。

生存は画面・戦闘phase・強化選択・復帰猶予・一時停止・可視性・フォーカス・接続を確認して入力を読む。進撃も同じ種類の操作可能条件を確認し、既存の0.05秒の移動予測を同じ入力採取へ移す。ソロのsimulationは既存の描画内ループを維持する。毎frameとタイマーの二重採取はしない。

切断・致命エラー・closeでタイマーを止め、新しいwelcomeとWorldを待って再開する。古いsocketのcallbackは再開させず、再接続後に押しっぱなしや切断中の短押しを持ち越さない。中断時に未送信の短押しを破棄し、送信済み入力のACK待ちは保持する。進撃の一時停止中は中立入力の連続送信から送信停止へ変わるため、最後に受理された入力の停止は従来のサーバー有効期限250ms以内となる。停止操作を即時受理する保証はしない。

## 検査方法

`scripts/check-network-input-ui.mjs`で実際の生存・進撃入口、通常の参加/出撃ボタン、キーボード・マウス、実ローカルWorkerを使用。使い捨てプロファイルへ名前の設定だけを置き、本人のセーブは使わない。RAF callbackの配達だけを1000ms保留し、250ms後に移動キーと射撃を離す。実WebSocket送信を観測するが、transportやサーバー判定は置き換えない。計測値は操作解除から送信までで、サーバー受理や人物の表示までの遅延ではない。

修正前はc5521c1のproduction build（revision `70a1fc3ac3acde4cbf8c929c6bda86763184f85c97cd2d8366a5c4871118ea9c`）。source hashには検査時のworktreeも記録するが、修正前画面へ現在のソースを配信したという意味ではない。修正後はViteで追加修正済みソースを配信。別seed・別起動条件なので一般的なFPS改善率へ読み替えない。

結果は[集計JSON](network-input-results.json)へ保存。原本は`dist-validation/coop-comfort-20261030/`以下。集計は`node docs/evidence/coop-comfort-20261030/summarize-network-input.mjs`。実画面検査は5186へViteまたは旧build preview、8793へ`wrangler.test.jsonc`の隔離Workerを起動して実行する。`SWARM_INPUT_BASELINE=1`で修正前、`SWARM_INPUT_UI_MODES=front,legacy`で対象を選び、`SWARM_INPUT_UI_OUTPUT`は毎回別にする。

修正後の一時停止メニューと縦画面案内では80ms後以降の入力送信が両入口とも0。切断中のQ短押しを持ち越さず、再接続後1050msの送信は生存20件・進撃18件で、古い射撃・移動・回避・装填・切替は0。画面例外0、計測中source hash不変。[生存画面](network-input-front.png)、[進撃画面](network-input-legacy.png)は実描画とHUDを目視確認。タブ切替の未確認は下記のとおり明示する。

関連単体は入力21件・状態送信15件・受取確認7件の計43件に成功。welcome前の停止、重複welcome、両Networkの再接続/close、遅いACK下の短押し保持、解除、callback内で3秒停止した後に追いつき連送しないことを含む。client/workerの型チェックも成功。以前の92件などは先行実装時点の結果として保持し、今回全件を再実行したとは記さない。

4個のChrome processすべてが描画する45秒の実通信では、4人の移動・射撃・装填開始・命中を観測。敵省略/途中切断/画面・GL例外0、World受信434〜436回、最大packet16,709B、source不変。`check-coop-live.mjs`のpilotも製品の`NetworkInputLoop`から採取し、RAFから直接送る旧検査とは分けた。

ただし同じPCの描画資源を4processで共有したこの条件ではframe p95 33.4ms、最大383〜467ms、猶予外の入力間隔250ms超が各1件（最大264〜412ms）、猶予外ack=0が0/1/0/1件残る。機能検査の`passed=true`を快適さの完全合格としない。入力を別タイマーへ移しても、描画以外も含む処理待ちをなくす保証はない。

負荷の切り分けとして4接続/描画1画面、各方向75ms・131,072B/sの未圧縮payload制限で60秒確認した（`live-input-loop-single-render/`）。猶予外ack=0と250ms超の入力間隔は全員0、入力最大間隔は74.5/67.7/66.8/66.9ms。描画frame p95 16.9ms/最大33.4ms、画面・GL例外/切断0。適用ACK応答最大504〜523msは回線条件下に残る。4画面試行とはseed・回線条件も異なり、数値差を同条件の改善率とはしない。この60秒で先行の単発RAF待ちを永久に解消したとも、実スマホで同じ性能になるとも保証しない。

## 検査途中の失敗と限界

実装commit後のbuildは233 modules/6.18秒、Worker production dry-runは443.39KiB/gzip113.35KiBで成功。最新revisionの150件保存・中断再開・差分更新・通信なし生存出撃も確認。[PWA統合確認](pwa-implementation.md#入力採取を分離した追加版の統合確認)。main反映・既存Worker公開・実機確認は未実施。

- 最初の生存検査は画面遷移中の「準備完了」クリックが既存guardに止められた。2frameと遷移終了を待つよう検査を修正し、製品guardは変更しない。
- 先行Workerの検査用データが部屋作成100件/日に到達し、進撃側が429になった。既存データを保持し、別の空のローカル検査用データへ切り替えた。製品制限を変更していない。検査client識別子は既存契約どおり64桁hexに修正。
- 旧buildの初回名前登録後に参加が続かず、出撃待ちが時間切れになった。原因未確認。今回の入力周期検査は名前設定だけを持つ復帰者条件とし、初回登録全体の合格とは記さない。
- Vite初回の依存準備でloadが65秒を超えた。準備後の再実行と区別する。
- タブ移動後の`document.hasFocus()`がheadless/実ウィンドウ両方でtrueのままだった。ローカルのPlaywright実装が`Emulation.setFocusEmulationEnabled(true)`を設定していることを確認。実ウィンドウと別CDP sessionでfalseを送っても元の設定は解除できなかった。最終結果の`nativeFocusVerified`と各`verified`に未確認を明記し、この項目を製品の合格にしない。製品のfocus判定を上書きしない。入力sourceが無効な時の停止・保留破棄は単体で検査し、実タブ切替は実機確認へ残す。
- スマホ実機、iOS Safari、実回線の複数端末、長時間の発熱は未確認。先行診断で残る単発RAF待ちの根本原因を、この入力分離で解消したとはしない。
