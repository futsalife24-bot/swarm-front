## 確認した不具合と修正

1. `server/worker.ts`の50ms間隔時計が遅れを毎回積み上げ、実時間30秒に対しゲーム時刻が約22秒しか進まなかった。絶対締切を持つ`RoomClock`で次の待ち時間を補正する。物理計算は従来どおり0.05秒単位。250msを超える遅れは無制限に追い付かず記録して時計を立て直す。停止/再開中の古い非同期callbackから時計を二重起動しない世代判定も追加。
2. 敵弾と共有の100個上限により、プレイヤーの弾が発生しなくても弾薬と発射演出だけ消費される場合があった。合法な射撃の実体弾を生成し、ロケットは移動線分の最初の接触を判定する。[詳細](projectile-diagnosis.md)。
3. 64KiB送信上限のため敵情報を省略し、新規の敵は見えず、既知の敵は古い位置へ留まる場合があった。丸め済みの同じ値を可逆な配列と共有ID表へ詰め、全情報を送れる範囲を広げた。なお大きいWorldは、対応を交渉した接続に限り最大256KiB/16片へ分割し、全片の長さ・順序・checksumが一致してから適用。部分適用しない。2秒期限と切断時破棄を設け、旧接続と64KiBフレーム上限は維持。[形式・互換・サイズ・単体検証](wire-tuple-diagnosis.md)。256KiB超の無制限保証はしない。
4. 敵のGPU姿勢処理が同じ行列を二度読み取る場合を一度にした。中間姿勢の補間は維持する。モデルの形・ポリゴン数はまだ変更していない。後述のPC計測ではFPS改善を確認していない。
5. 受信に成功しても通常弾160発・光線100発までしか描画できず、光線のカウントがバッファ外へ進む問題があった。受信Worldの上限と同じ4096発までのバッファと範囲ガードに統一。保存・武器性能・命中判定の数値は変えない。

追加の遅延調査で遅い回線へのsnapshot滞留を確認し、接続ごとに未ACK2状態へ制限する送信制御を追加。制限下で最大適用応答1.34秒→0.53秒、通常4画面再検査で数秒の滞留は再現せず。単体81件、最後の結果・旧接続共存の実通信1件、既存互換6件、大量描画・再接続が成功。[追加修正と検証・限界](state-flow.md)、[入力遅延の調査](input-latency.md)、[World容量の境界](world-bound.md)。
