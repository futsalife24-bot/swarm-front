# 協力部屋1人出撃の歩行表示を改善（2026-10-30）

## 本人の条件と原因の範囲

本人回答で、録画は **OPPO Find X8・携帯回線・協力部屋を立てて1人で出撃** と確認した。通信を使わないソロではない。OS/ブラウザ、回線の実測遅延、録画時の読み込み版は未確認。原本動画と切り出し画像は公開しない。

生存の協力入口 `front-app.ts` は、受信したWorldをRendererへ渡し、自機位置にもサーバー応答待ちがあった。進撃側の既存の予測をそのまま転用せず、接地歩行の表示に限定して実装した。動画の59〜60FPSは入力応答の速さを保証しない。事前保存は素材の取得待ちへ効くが、この応答待ちを短縮しない。

これは確認できた遅延経路への修正であり、本人の症状すべての原因を確定したものではない。サーバーの処理・実回線・命中結果の往復遅延や実機GPUの負荷を今回解消したとは扱わない。

## 変更

- `front-local-motion.ts`: 自機の接地歩行だけを実時間に沿って7m/sで表示。World・当たり判定・他プレイヤー・通信形式・保存に変更なし。各パケット数を移動時間に変換しない（同じ入力が複数tick適用されるため）。
- 先行を権威位置から3.15m以内に制限。500msの受信途絶、100msを超える描画間隔、非操作状態、死亡・再接続・run切替で解除。値は今回の安全上限で、全回線を快適にする保証ではない。
- 停止時は解除操作の適用ACK、または600msを待って有限速度で位置を合わせる。受信通知だけのACKを適用完了と見なさない。
- 既存の衝突判定を使い、段差・空中・回避・KB-6発射・大きな変位では権威表示へ戻す。空中/回避を不完全に再現して壁抜けを増やさない。
- `input.ts`: 表示用に方向を読む `previewMovement()` を追加。送信番号やジャンプ等の一度だけの操作を消費しない。`front-app.ts`で実際の入力採取・受信・描画・中断へ結線。

表示がサーバーより先行する間、敵・弾・被弾・命中結果は引き続きサーバー基準になる。通信自体が長く遅れる条件ではズレや補正が残る。回避とジャンプの応答を即時化した修正ではない。
