# 補給ポッド10案・新ガチャの検証

本人が元動画10案の採用、新ガチャ新設、確率/券/10連保証、本体接続・公開を承認。改善5案は混ぜていない。仕様は [今回の記録](../../SUPPLY-KAKUTEI-20261111.md)。

## 描画の照合

元の動画生成コードと移植先を、844×390・deviceScaleFactor2、同じ時刻/FX値で57画面ずつ撮影した。48画面はJPEG復号画素が完全一致、残り9画面の平均絶対差の最大0.00907/255。全結果は `fidelity-diff.json`、全画像は `reference-stills/` と `ported-stills/`。通常Canvas/FX式は文字一致、11素材とCSS・効果音Workerも一致。音の波形生成・mixは原本のまま、音量設定と破棄時の解放だけ追加。

比較字幕は同一表示し、本体では説明用番号/文言を重ねない。ユーザーの任意のタップ待ちまで動画と同じ尺とは主張しない。演出部分の元の秒数・式を維持し、実操作の停止点へ接続した。

## 操作と本体

- 表示Chrome：10案の実時間タップ完走、10連中の⑤～⑩、17条件のFX/音合図順序/通常・動き減/スキップ/cleanup成功。⑦の通常タップと途中離しでも完走。
- 自己レビューで金射出の待機色、part境界の時刻位相、2回目の画面割れsnapshotを修正。軽量17条件と金文字/2回目snapshotを再確認。
- 本体Chrome844×390/640×360：新規進行確認→初回バディ選択→基地→補給→実HTTP10連→保存→途中再読込み→同じ結果回復→スキップ→ACK→基地まで完走、pageerror0。武器ID/受領ID/武装片は回復前後で同じ、二重付与なし。`game/results.json`。
- `*-menu.png` は遷移中の撮影。配置の証拠は `*-menu-stable.png`。撮影器の初回確認/バディ選択の待機不足は失敗として残し、待機を直して成功。製品の保存エラーと混同しない。
