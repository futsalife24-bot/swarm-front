## 実装

- helloで交渉した接続だけ、戦況2枠が詰まった時に限り、操作受信確認を10Hz上限の小さいinputReceiptで返す。戦況の未ACK2枠から独立。入力の実適用確認は従来Player.ackのままで、受信と適用を混同しない。旧接続へ新応答を送らない。
- 新方式の戦況ACKは200ms超の受信空白または往復時間の時だけ100msの待ちを省く。正常な更新は入力への同梱を待ち、不要な単独通知を増やさない。単独ACKは10Hz上限、通常の入力への同梱を維持。既存受信35件/秒制限・入力50ms間隔・未確認枠・250ms入力失効を緩めない。
- ACK済みstateIdを基準として、top/world/frontの変更キー、敵・弾・オーブtupleの変更fieldを送る。fullよりUTF-8サイズが小さい場合だけ採用し、最大49差分後に全量を挟む。送信側は基準＋pending2件、受信側は直近3件。各完全状態は256KiB以内。基準をJSON保存し、tuple復元/装備補完による利用側の変更から切り離す。
- 不正差分や基準欠損は通常再接続へ。送信失敗では差分基準を破棄。hibernation/再接続では全量から再開。大きな差分も既存分割・checksum・2秒期限を通す。差分化できない状態は全量へ戻し、元のサイズ制限を守る。
- ローカル計測は入力採取→送信、送信→受信確認/適用状態/描画提出、戦況間隔、入力timer遅れ、受信処理、サーバーstep/前回encode/時計遅れ/未ACK枠。各128標本・入力64件の上限を持つ。端末とサーバーの時計差を一方向遅延として出さない。GPU表示完了や指が画面に触れた瞬間を測るものではない。
- 診断が必要な時だけ front.html?networkDiagnostics=1 でwindow.swarmNetworkDiagnostics()から集計を読める。名前・token・入力内容・保存データ・自動外部送信を含まない。通常HUDの仕様は変更しない。

## CPU負担の削減と測定上の制約

初版差分codecの実戦encode p95が9〜11msになったため、そのまま公開せず重複parse/stringify/構造走査を減らした。同じ制御fixtureの交互反復でencode平均8.46→1.70ms、p95 16.24→2.90ms、decode平均3.12→2.15ms。wireサイズと周期full回数を維持。2,560状態をdeepStrictEqual確認。[測定条件・hash・結果](state-delta-codec-cpu.json)。このCPU実験の旧版は公開済み旧コードではなく、今回の初期実装である。

実画面比較は同じローカルWorker/Chrome、通常操作、空プロファイル。legacyNegotiationは新機能の交渉を外して既存方式を使う比較で、旧公開版全体を動かす比較ではない。部屋ごとにseed/敵配置は異なり、厳密な性能倍率や因果の証明にしない。帯域は圧縮前WebSocket payloadに加えた合成制限であり、携帯回線の実効帯域/通信料金と同一ではない。PCのFPSをスマホ性能の証拠にしない。

診断p95は直近最大128標本の集計。送信→適用状態は送信番号に対する権威側Player.ackの受信、描画提出はrender呼出し後まで。GPU表示完了ではない。入力採取はnetwork loopの採取時刻であり、物理タッチ時刻ではない。実サーバーの時刻精度の影響があるため0msを処理ゼロと断定しない。

500msの端末メインスレッド停止を検証で注入し、入力timer遅れの検出とその後の更新復帰を確認した。844×390と640×390の画面で既存左下表示が収まり、画面例外0。実OPPO/携帯回線/複数実端末/長時間発熱/全症状解消は未確認。
