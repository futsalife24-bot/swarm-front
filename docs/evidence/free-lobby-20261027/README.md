# 募集方式の待機画面：検証証拠

`ui.json` は `scripts/check-lobby-access.mjs` が、隔離ローカルWorkerと空のChromeプロファイルで実行した8条件（生存/進撃 × 公開/非公開 × 844×390/640×360）の配置を記録する。方式ラベル、画面内の主要ボタン、ボタン同士の非重複、横方向のはみ出し、パスワードコピー、生存の招待リンクコピーと画面エラーを検査した。保存データ・表示名・部屋は合成で、本番部屋は使用していない。

各PNGは640×360の実ブラウザ画像。画面表示の確認であり、実スマホ、実インターネットでの多人数接続、全端末の安全領域を確認したものではない。画面の部屋番号は隔離Workerの検証用。ロビーの画像取得は戦場モデルの読込完了を前提としない。

手動の隔離アプリ内ブラウザでは、生存と進撃で各1人の準備完了を確認した。自動検証のViteログにはページ終了付近に兵士モデルの取得失敗・代替表示の警告があり、原因は未特定。初回の自動検証は画面切り替え中の入力保護や進撃側の未登録プレイヤー名を考慮できず待機がタイムアウトした。検証側を修正して上記8条件を通した。
