## 崩さないでほしい設計判断

理由があって選んだものです。変えるなら理由ごと書き換えてください。

1. **`stats(weapon)` が武器の実効値の唯一の出所。** 戦闘・HUD・武器庫がすべてここを通る。
   `WEAPONS[kind].mag` などを個別に直接読むと、表示と実挙動が食い違う。
2. **振れ幅は基準の上下**（0.80〜1.25）。上振れだけにすると全項目最大の1本が再び全てを支配し、
   「1本引いたら終わり」に戻る。完全上位互換の発生率は現在約2.2%（旧設計はほぼ100%）。
3. **装填だけ「小さいほど良い」。** `LOWER_IS_BETTER` で反転させている。
4. **弾数は整数丸め＋最低1発。** ロケットは基本2発なので、割合だけで丸めると半減する。
5. **LRの威力上限はSSRと同じ**（`POWER.max[3] === POWER.max[2]`）。上位互換を作らず
   「全部引き当てた証明」として扱うため。
6. **威力上限をレア度に紐付けない。** レア度が後から決まるので、低レア度でも威力だけ高い個体が
   正当に存在する（その分を他項目で払っている）。
7. **HUDは100msごとに `innerHTML` を全置換する。** ここにボタンを置くとタップを取りこぼすため、
   一時停止ボタンは `index.html` の静的要素にしてある。
8. **効果欄は「数字で表せない能力」専用。** 高速装填は装填列の数字に出るので列には出さず、
   数字を金色にしている。
9. **更新履歴は `src/client/changelog.ts` に手で書く。** 遊ぶ人向けの言葉で、コミット文を
   そのまま載せない。変更を入れたら1行足すこと。

## テスト実行時の既知の罠

詳細は `docs/TESTS.md`。

- **E2Eが起動待ちで止まったら、残っている `workerd.exe` を殺しても直らない。**
  `npm run server` / `server:test` の親プロセスが子を再生成し続ける。親から止めること。
- **協力テストを短時間に繰り返すと、受付制限に自分で引っかかる。** Gateは同一クライアントの
  部屋作成を10分あたり10回に制限する（記録は最初の接触から10分で消える）。`準備完了` が出ずに
  `toBeVisible` で落ちたらこれを疑い、時間を空ける。確認は
  `curl http://127.0.0.1:8789/admission-stats`。
- **手動で作った BrowserContext はテスト終了時に閉じられない。** 開いたままだと次のテストへ
  フォーカスが漏れ、キー入力が別ページへ飛ぶ。`bringToFront()` と `close()` を使う。
- `--reporter=line` の出力を `tail` へ通すと完了まで何も見えない。ログはファイルへ落とす。

## 残っているタスク

`docs/BACKLOG.md` に理由つきで記載。

1. **高速装填を効果枠から外すか（要判断）。** 外す場合 `Weapon` の形が変わりセーブ移行が必要で、
   さらに**ロケットが効果を1つも引けない系統になる**（貫通はロケットに付かない仕様のため）。
   埋めるにはロケット専用の効果を1つ足す必要がある。
2. **フレンドリーファイア・自爆。** 順番が重要で、蘇生が実機で直ったことを確認してから着手する。
3. **位置ゲー機能（現実GPS）。** ブロックの大きさが未確定。プライバシー方針と位置偽装耐性が新たに要る。
4. ステージ・地形の追加、蟻型、蜘蛛の壁張り付き、巨大ミミズ型ボス（P2〜P4）。
5. ユーザー名の登録と味方頭上のHPゲージ（P1の残り）。
