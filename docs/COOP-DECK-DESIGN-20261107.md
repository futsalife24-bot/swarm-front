## レイアウト判断（確定版）

既存 front-base の要素・見た目は全部残し、**段の置き場所だけ**を変える。

```
┌ カードデッキ編成 [武器は固定：ライフル] 再抽選2回 ─────── [保存して準備完了][ロビーへ戻る] ┐
│ [強化25][融合9]            発見0/9·狙える融合5 │ 次は進撃4：…        抽選17/17種·除外0/1 │

│ 状態表示（保存結果・エラー）                                                          │
└──────────────────────────────────────────────────────────────────────────────────────┘
```

1. **デッキ枚数の段を詳細欄の上へ移す**：全幅だった `.base-deck-bar`（次の獲得・抽選数・除外枠）を右列の上、タブの段の横へ置く。除外枠の数字が除外操作と同じ列に並ぶため意味も近くなる。縦の1段（約22px）をカード格子へ回す。DOMは変えず、`.front-departure-deck` を4段2列のgridにし、配置用の `.base-workbench` だけ `display: contents` にした。重ね置き・固定座標はない。
2. **詳細欄の上端と格子の上端をそろえる**：タブの段は36px（高さ370px以下では34px）、右上の段は「タブの段 − 段間」の30px。
3. **主操作を44pxにする**：保存して準備完了・ロビーへ戻る・抽選から除外の3つ。既存の36/40pxから上げた。ヘッダーは約8px高くなるが、1の効果の方が大きい。
4. **固定武器は見出し内の小さな補足**：`.front-departure-weapon` を枠付きの11px文字にする。武器を選ぶ欄・武器カードは置かない。名前が長いと省略記号（844幅で最大15em、700幅以下で11em）。省略時の全文は `title` 属性で補うことを推奨。
   4b. **再抽選の回数は縮めない**：`.base-service` は11px・縮小なし。見出しで縮むのは固定武器の補足だけにする。幅600px以下（568幅など）では、3ボタンと再抽選の回数を優先し、固定武器の補足を出さない（2026-11-07 修正版）。
5. **低い横画面（高さ370px以下）**：段間を6→4px、ヘッダー下の余白を6→2pxにする。
6. 次の獲得の文が長い時は最大2行で切る。抽選数・除外枠は太字で右寄せにし、折り返しても右下に残す。

適用範囲は `.front-departure-deck` の配下だけ。ソロの生存カード画面（`?cards=1`）にこのCSSを読み込んでも、寸法は変更前と同じだった（下の検証）。

## 修正版（2026-11-07）：nav 3ボタンと568幅の再抽選回数

- 実装側の契約：見出しは `h1` →`.front-departure-weapon`→`.base-service`→`nav`（保存して準備完了 / ロビーへ / 設定・操作）。協力の生存戦だけに適用する。ソロ・防衛・デイリーの既存の出撃準備は変えない。
- Codexの実画面（`task-coop-lobby-deck/dist-validation/coop-lobby-deck/deck-844.png`・`deck-640.png`・`deck-568.png`、新しい実装の画面）では、568幅で固定武器の補足と「再抽選 N回」がどちらも省略されていた。
- 対応（CSSのみ）：
  - `.base-service` を縮小なし・11pxにする（既存の700px以下の10pxより強い指定）。
  - 幅600px以下では `.front-departure-weapon` を非表示にする。600pxより広い時も、縮むのは補足だけ。
- 実画面とソースからの見積もり（独立Viteの再試験はしていない）：
  - 568幅：見出しの空き幅は約179px（h1の右端から nav の左端まで）。「再抽選 N回」は11pxで約60〜70px なので、2桁の回数や左右44pxの安全領域があっても収まる。
  - 640幅：補足と回数の後ろに約45pxの余白がある。回数を10→11pxにしても補足は省略されない見込み。
  - 3ボタンは44pxのまま。並び順と幅は変えていない。
- 最終の3サイズの再試験はCodexが担当する。
- 気付いた点：実画面ではカード格子の上に「接続済み」の通知が重なっている。このCSSの範囲外の既存通知で、時間で消えるなら問題はない。
