### 散弾・多段・継続ダメージの扱い

- **同じtick（0.05秒）の被弾は1回の被弾**として扱う。散弾8ペレット・貫通・爆風・誘爆・前線の跳弾/迎撃/地雷が同時に当たっても、軽減率も「連続かどうか」もそのtickの最初の有効被弾の時点で固定する。ペレットの処理順で結果が変わらず、1発の散弾が自分自身と連続になることもない。
- **連続判定は、前のtickまでの最後の有効被弾の時刻**で行う。誰の攻撃か・何の武器かは問わない（協力の交互射撃も連続になる）。
- **硬化の加算は個体全体で0.10秒に1回まで**。協力4人の集中射撃でも上限は1人と同じ（実Workerで2人が撃つと75以上に1.3〜1.4秒、100に約1.7秒。送信の間隔で0.1秒ほど揺れる）。
- **相が変わったtick**（赤予告→開放、開放→通常）では、その後の被弾（敵の処理より後に計算される爆風・誘爆）に新しい相の軽減率を使う。連続判定と加算の上限はtickの最初の被弾のまま。
- **継続ダメージ**は現行ゲームの敵向けには存在しない。将来追加した場合も各tickの被弾が上の規則に入るので、加算の最大速度はSMGと同じ（+8/0.1秒）で頭打ちになり、瞬間硬化は起きない。より弱くしたい場合は `bastionDamage` に発生源の種別を渡す拡張が必要（未実装）。
- 0以下のダメージは連続判定にも減衰の延長にも使わない。

制作中に見つけて直した不具合: 初版では同じtickの2粒目が1粒目と「連続」と判定され、散弾1発ごとに+8されていた（シミュレーションで最大硬化32を検出）。tickの最初で連続判定を固定する形に修正し、回帰テストを追加した。

### 撃破時間の目安（ソロ・距離12m・ステージ補正なし、実 `step()` のシミュレーション）

| 武器と撃ち方 | 撃破まで | 反撃回数 | 最大硬化 |
|---|---:|---:|---:|
| AR 撃ち続け | 3.0秒 | 1 | 100 |
| SMG 撃ち続け | 2.95秒 | 1 | 100 |
| LZ-2 レーザー | 3.05秒 | 1 | 100 |
| AR 0.4秒撃って1.4秒休む | 7.3秒 | 0 | 68 |
| SG-4 散弾 | 3.2秒 | 0 | 0 |
| SG-7 スラッグ | 2.55秒 | 0 | 0 |
| SR-1 スナイパー | 2.1秒 | 0 | 0 |
| RL-2 ロケット | 3.8秒 | 0 | 0 |
| 参考: CALYX（硬化なし）を AR で | 1.85秒 | — | — |

散弾は距離と拡散の乱数で当たる粒の数が変わるため、条件によって結果がぶれる（別セッションのレビューの再計算では2.4秒・硬化0）。

連射武器では撃ち続けても倒せるが、必ず反撃を1回受ける位置まで硬化する。単発武器・散弾は硬化させずに倒せる。断続射撃は反撃を避けやすい代わりに遅い。ステージのHP補正や協力人数補正で耐久が増えると、硬化→反撃→開放の周期を複数回見ることになる。

### 試作案に対する判断と代案

- 試作案（段階到達→明確な予兆→放射弾、硬化で弾数増、反撃後に開放）は既存の予兆規約と弾の仕組みにそのまま乗るため採用した。
- **代案A（安全側）**: 弾数を6/9発、弾速8m/sにする。12発でも10m以遠の隙間は3m以上あるが、近距離の協力戦で混雑する場合の調整案。
- **代案B（開放の強調）**: 開放中だけ被ダメージ+25%。今回は「新しい弱点判定・倍率を増やさない」方針で未採用。
- **代案C（反撃なし版）**: 硬化だけで反撃をなくし、最大硬化で移動速度だけ下げる。脅威が弱すぎるので不採用。

- **master** `bastion_master.blend`: 高分割（約24.7万三角形）、3段の面取り、手続きPBR（塗装・縁の欠けと露出金属・凹部の汚れ・細かなひび・錆の斑点・擦り傷、Cycles）。状態別の実レンダー（同じカメラ・照明、Cycles 64サンプル）、正面/側面/背面/上面、単色の輪郭を出した（証拠フォルダの master-*.jpg）。
- **ゲーム版** `bastion_v1.glb`（`public/assets/enemies/` へコピー）: 低分割（17,636三角形）、1段の面取り。外装と骨格を1枚のUVアトラスへ焼き込んだ BaseColor／metallicRoughness（各1024、JPEG）。剛体ノード（Body・band・band_ports・core・cage・seams・plate×8・spike×10）と、開閉軸・浮き方向・トゲ方向を extras に持つ。骨・アニメーションクリップはない（姿勢は状態から毎フレーム計算）。

形の手順は「大きな形（球・赤道帯・上下4枚）→厚み・接合（面取り、溝と裏当て、受け座、リブ、継ぎ目の関節リンク）→曲面と分割（冠パネル・帯の補強リブ）→材質（PBR・摩耗）」。各段階で実レンダーを見て直した（位置ずれの修正、帯の補強追加、2段パネル化、摩耗の強化、トゲの太さ、正面配置、継ぎ目の関節リンク）。継ぎ目の関節リンクは master が7度間隔・面取りあり、ゲーム版は14度間隔・面取りなし。

## 既知の問題・未対応

- 出現の数・時刻・攻略の配置は仮値。本人の実機確認後に調整する前提。
- エネミーレポート本文・声・会敵動画は未制作。未遭遇扱いのまま記録しない。反撃の予兆に専用の音はない（既存の着弾音の「硬い殻」系を流用）。
- トゲ先端の外側半分は当たり判定外。
- 赤い危険帯は支持面へ1.5m区間ごとに沿わせた帯で、幅も区間ごとの高さで決める。段差の縁では区間の境目がわずかに浮く／沈むことがある。段差のあるマップでの目視確認はまだ（検証は平地）。
- 予告済みの斉射は既存の弾数上限100を一時的に超え得る（最大で同時予告中の BASTION 数×12）。描画枠は160に拡張。弾の一覧は敵と隊員で共有なので、合計が100以上の間は他の敵の弾に加えて、**隊員の弾道を持つ武器（ロケット・グレネード等）の弾も出ない**（既存の上限の仕様）。生存戦は同時1体に抑えた。攻略は1つの波に最大3体（ST24）で、同時に反撃すると最大36発が重なり得る。
- 撃破時は既存の撃破演出（kill イベントの破片）だけで、装甲が外れて落ちる専用の演出はない。
- GLB は攻略の出撃準備・生存戦の60秒以降・戦場に BASTION が現れた時のいずれかで読み込む（読込中は既存の簡易形状）。出現しない作戦（防衛・デイリー・出現8作戦以外の攻略）では取得しない。
- 球体のため前後の輪郭差はない。向きは照準弾の発射口と開放の向きでだけ示す。
- ゲーム版GLBは17,636三角形・約1.55MB。FOUNDRY ZERO（18,680）より少ないが PRISM/RAY より重い。1体あたり描画呼び出しは約30。複数体の実機負荷は未測定。
- Android/iPhone の実機、Safari/Firefox は未確認。検証はヘッドレス Chrome（SwiftShader）と Node のシミュレーション、ローカル Worker。
- 既存テストのうち6件（照準・BGM復帰・RAY・地底マップ・描画）と、読込段階で失敗する `tests/weapon-stat-marks.test.ts` は、変更前の main（da41b38）でも同じく失敗する既存の不具合で、本変更とは無関係。
