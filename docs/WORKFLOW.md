# mainを正本にする開発手順

2026-09-15 ユーザー指示: **mainから作業開始 → 変更を保存・検証 → mainへ反映**。1タスク・1セッションを基本とする。

## 正本と開始点

- GitHub: `https://github.com/futsalife24-bot/swarm-front.git`、既定ブランチ `main`。
- 通常のローカル作業場所: このリポジトリ（スワフロ配下の `game/`）。親フォルダーのGit・旧コピー・別プロジェクトは使わない。
- `origin` は上記GitHub。`local-archive` は旧ローカル接続先の保管名で、push/pull先ではない。
- 現在地は `docs/STATE.md` 先頭と実際のGitを照合する。下部の履歴や古いHANDOFFに書かれたブランチを無条件に使わない。

## 開始

1. `git rev-parse --show-toplevel`、`git remote -v`、`git status --short --branch`、`git log -1 --oneline` を確認する。
2. 未コミット・未追跡の成果があれば保護する。自動reset/clean、無断stash、別タスクの変更を巻き込んだcommitは禁止。STATEの未完了作業が今回の継続なら、その記録されたブランチから再開する。
3. 通常の新規タスクはcleanを確認して `git fetch origin` → `git switch main` → `git merge --ff-only origin/main`。ローカルmain独自のコミットがあればforceせず原因を確認する。
4. 最新mainから `git switch -c codex/<今回の短いタスク名>`。同じディレクトリで進め、不要なコピーを増やさない。並行作業が必要な場合だけ明示的に別worktreeを使い、場所を記録する。

## 保存・検証

1. 今回の差分と必要な依存関係を自己レビューする。ゲーム本体・認証・通信・保存に作用する変更は型チェック、影響範囲の単体/実通信/UI確認、関連ビルドを行う。文書だけならリンク・内容・差分を確認し、無関係な全件テストを増やさない。
2. 既存失敗を新しい回帰と区別する。必要な検証が失敗したものを合格扱いしてmainへ入れない。修正または具体的な受入判断に必要な証拠を残す。
3. 素材は実行時に必要なもの・原本・再生成手順を保存する。秘密情報、依存キャッシュ、dist、使い捨ての画像/動画/ZIP・監査コピーを無条件に追加しない。既存保管物の削除や履歴書換えは行わない。
4. `docs/STATE.md` 先頭へ、今回の内容、検証、未完了事項、詳細記録へのリンクを簡潔に記す。関係ファイルを明示してstageし、`git diff --cached` と差分一覧を確認してcommitする。
5. 外部共有前に秘密情報・100 MiB超ファイル・不足する実行時素材を確認する。push先は既存GitHubで、force-pushしない。

## mainへ反映・終了

1. 作業ブランチをpushし、main向けPRに問題・変更・検証・残課題を記載する。通常のcommit/push/main反映は2026-09-15の継続指示で許可済み。同じ承認は取り直さない。
2. 既存の明示的なChat独立監査、ブランチ保護、必須CI、個別の承認条件を満たす。Codexの自己レビューを外部監査合格に代用しない。mainが進んだ場合はfetchして取り込み、競合と影響範囲を再検証する。
3. 条件を満たした対象HEADをPR経由でmainへ反映する。管理者バイパスや保護無効化はしない。
4. cleanなローカルでfetch → mainへ移動 → `git merge --ff-only origin/main`。リモートmain、origin/main、ローカルHEADの一致と、未コミット/未追跡差分がないことを確認する。
5. 完了報告はmainのSHA、PR、変更、検証、残課題を簡潔に示す。次のセッションはmainから開始できる状態にする。

**反映前に止まる場合:** 完成と報告せず、成果をcommit/pushして保護し、STATEへbranch/HEAD、PR、検証結果、停止理由と再開条件を記す。外部監査や個別承認を待つ間、独立して進められる準備を終える。次の新規タスクを旧mainから始める前に、この未完了集約を解消する。

**公開との関係:** GitHub mainへの反映とCloudflare Workerへの公開は別操作。既存公開物の整理だけで不要な再デプロイをしない。公開した場合はソースSHA・Worker Version・配信照合結果を記録し、main反映済みかも分けて報告する。

## Chat独立監査への素材添付（2026-09-16ユーザー指示）

Swarm Frontの監査依頼では、初回から対象commitの必要なGLB・Blender原本・比較動画/画像・検証証拠をZIPにして通常の監査Chatへ直接添付する。非公開の当該プロジェクト素材を監査目的でそのChatへ送ることはユーザー承認済み。PRリンクだけでバイナリ取得できる前提にしない。対象SHA・ファイル対応を明記し、秘密情報・無関係な個人情報・対象外素材は含めない。新規監査は新しい通常Chat、追加証拠は同じ監査Chatへ渡す。
