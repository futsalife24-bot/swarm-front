# 成長循環の敵バランス測定（2026-10-14）

## 対象と方法

- 証拠: [`baseline.json`](evidence/growth-balance-20261014/baseline.json) は統合HEAD `1be6f31` の旧係数による36条件、[`candidate.json`](evidence/growth-balance-20261014/candidate.json) は未コミットの候補係数による48条件。測定手順は [`measure-growth-balance.test.ts`](../scripts/measure-growth-balance.test.ts)。各条件はseed `814`・`723` の2回で、基礎比較は180秒上限。
- 生存作戦と進撃、進度ST0/10/25、人数1/2/4人を前後比較した。3人は候補側だけなので前後差は出せない。全員が同じ `STARTERS` 2本（レベル `1 + ST`、個別ID）を使い、候補選択は各回の既定カードとした。`tests/bot.ts` のpilotが通常入力を出し、角度を有効範囲に補正してゲームを進めた。HP・敵数・報酬を直接操作する測定ではない。
- 生存作戦は `createFrontRun` の融合サバイバルを通す。進撃の単独条件を含む全人数は `createWorld`、`addPlayer`、`start` による**共通戦闘**であり、`initSolo` 専用進行の測定ではない。
- `kills` は各プレイヤー撃破数の合計。baselineには `kills` フィールドがないため、報告時に `playerKills` の合計から導出した。原データは変更していない。`taken` は各tickの正のHP減少の積算で、回復は差し引かない。`spawned` は観測した敵ID数。`battle` は180秒時点で戦闘中を表し、勝利扱いではない。

## 候補係数

| 係数 | 旧 | 候補 | 意図 |
| --- | ---: | ---: | --- |
| 敵HPの人数倍率 | `1 + 0.55 × (人数−1)` | `1 + 0.75 × (人数−1)` | 1/2/3/4人で `1 / 1.75 / 2.5 / 3.25` 倍。一人当たり担当HPを、均等射撃ならソロ比 `1 / 0.875 / 0.833 / 0.813` にする。 |
| 生存作戦の進度HP | `1 + ST × 0.055` | 同じ | 敵HPの進度は維持。 |
| 生存作戦の進度攻撃力 | `1 + ST × 0.035` | `1 + ST × 0.025` | 高進度の被ダメを緩和。 |
| 生存作戦の進度出現頻度 | `1 + ST × 0.04` | `1 + ST × 0.03` | 高進度の同時圧力を緩和。 |
