# 横・斜め・後退と移行の追加比較

既存の現行/Jog/Sprint素材を使用。モーションや本番コードには変更せず、比較ページの入力方向とカメラ追従だけ拡張した。

左右2画面の左が現行、右が候補。同じライフルと背面ロケット、7m/s、斜め後方カメラ、前方固定照準。横・斜めも移動ベクトルを正規化し速度を揃える。

通常速度18秒の連続入力:

| 時刻 | 入力 |
|---|---|
| 0–1秒 | 停止 |
| 1–3秒 | 前進 |
| 3–5秒 | 右横 |
| 5–7秒 | 右斜め前 |
| 7–9秒 | 後退 |
| 9–11秒 | 左斜め後ろ |
| 11–13秒 | 左横 |
| 13–15秒 | 前進 |
| 15–16秒 | 停止 |
| 16–17秒 | 再開 |
| 17–18秒 | 停止 |

18–22秒は別テイクの0.5倍確認。前進→右横→後退→停止を各1秒の動画区間で示す（ゲーム時間は各0.5秒）。リセットは動画開始時とスロー別テイク開始時のみ。方向転換や停止の直前にはリセットしない。

後退・斜め後退は両候補とも既存の `Run_Backward`。専用の外部後退モーションを移植した比較ではなく、外部前進クリップから現行後退へ切り替わる現状を示す。

`StandardTrooper.update` を1/60秒単位で進め、既存の方向追従・足着地・姿勢ブレンドをそのまま使用。比較用の補間や追加の滑らかさ補正は加えない。入力は描画用シーンの規定変位で、オンライン対戦や権威サーバーを通したプレイ映像ではない。

再実行:

```text
npm run dev -- --port 5340
node scripts/record-run-directions.mjs
node scripts/encode-run-directions.mjs <既存FFmpegの絶対パス>
```

録画・数値証拠: `dist-work/run-transfer-20260913/directions/`。
`capture.json` に区間・各フレームの下半身クリップ・ブレンド値・腰の向き・足位置、`videos.json` に動画ハッシュと全フレームのデコード結果を保存。
正式採用や移行の追加修正は、この比較を見た後の判断とする。

## 追加収録の結果

- Jog/Sprintとも22秒・30fps・660フレーム。MP4全フレームをデコード成功。ブラウザ例外なし、全フレームの骨姿勢が有限値。
- 通常速度の後退への切替直後7フレームでの最大足移動量（モデル内座標、1/30秒当たり）は現行0.374m、Jog0.520m、Sprint0.484m。停止直後は現行0.136m、Jog0.230m、Sprint0.190m。
- この値は通常の脚の振りと腰の方向転換も含むため、足滑り量や合否の閾値ではない。候補は切替時の足運びが大きくなる場面があり、滑らかさに調整余地を残す。
- 各動画12場面のデコード画像を確認。後退の素材自体は共通でも、前の走りから引き継ぐ位相によって左右の足位置が異なる。
- 既存の `standard-trooper.ts` とJog/SprintのBLEND/GLBは前回記録のSHA256と一致。今回は比較ページの拡張と録画・検証スクリプト追加だけ。ソースの構文確認と実ブラウザでの全収録を検証として実施。
- ブランチ `codex/home-armory`、HEAD `4186f25f7c9695f95ea897ad182db5f85fac3091`、未コミット。既存の変更は維持。
- 追加2本へのユーザー明示承認後、同じDriveアカウント・専用フォルダへ保存成功。メタデータでファイル名・バイト数・保存先・所有者限定の非公開状態を確認。検証記録は `directions/drive-sharing.json`。
