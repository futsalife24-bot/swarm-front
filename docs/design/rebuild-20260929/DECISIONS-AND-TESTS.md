# 共同設計の採否と検証

2026-09-29。共同検討後の推奨。実装の承認でも実測結果でもない。[設計正本](DESIGN.md)。

## 対立点をどう解消したか

|論点|最初の案|最終推奨と理由|
|---|---|---|
|尺|Codex 8〜10分 / Opus 約7分|戦闘目標約7分、実所要別計測。進化の時期を別途測る|
|支援|Codex 自動2枠 / Opus 行動起点|手動行動起点。短い追撃は許容、常駐自律火力は外す|
|進化|条件後に進化カード / 中ボス報酬|同系統3枚で追加能力を自動解放。2枚保持で3枚目保証、最大2進化|
|協力選択|共通停止 / 敵生成だけ止める8秒|残敵/弾の被弾を避け共通全停止、全体15秒、残敵は持越し|
|未選択/切断|同一自動確定 / 切断中は保留|全員同じ期限と既定規則。再接続で候補や構成を振り直さない|
|防衛|最初から拠点あり / 防衛を後回し|成長だけP1、同じ条件に防衛を加えP2比較。ユーザーの防衛志向は保持|
|最小範囲|3系統12カードから|1系統3枚＋汎用3種＋進化1。成立後に9枚＋汎用3種＋3進化へ|
|候補枯渇|最小6種類で7取得は不足|汎用3種を各4段階に。2〜3段階だけでは全経路の3択を保証できない|
|迎撃進化|三角地雷＋常駐子機|地雷起爆→次の手動命中の迎撃。低い制作範囲で操作との連携を試す|
|大群|敵数拡大 / 至近背後補充|まず既存制約内。出現口と予兆で公平さを守り密度/撃破頻度を測る|

## Codexが統合時に具体化した仮仕様

Opusとの共同推奨に加え、設計を読み進められるようCodexが補った事項。Opusが全文を逐語承認したとは扱わない。

- 補給時刻、戦闘9:00の試作上限、ボス中は新しい取得権なし。
- 既定候補の固定順、再抽選2回、汎用カード効果の仮数値。
- カードが単独でも効くよう、印/貫通/装填の発動条件を補足。弱点判定依存を初回から必須にしない。
- 同一対象/1射ID、チャージ上限、非公開データと公開状態の境界。

## 試遊・実装の合格目安

|問い|方法|作り直す兆候|
|---|---|---|
|初発動の手応え|1分後に本人の言葉で変化を説明|数値を見ないと違いが分からない|
|連鎖の操作|狙う最初の敵を変えて比較|どこを撃っても同じ、棒立ちが唯一の正解|
|構成の選択|3構成を経験後、自由に再挑戦|単一構成/最高レア一択、違いが説明できない|
|成長速度|各XP閾値到達/選択/進化/終了の戦闘時刻|7取得に届かない、進化後60秒未満が続く|
|協力待ち|速い/遅い選択者、複数ストック、切断を実2人で測る|累計停止が長い、選択が届く前に期限、復帰不一致|
|候補/不正入力|全取得経路、保証、再抽選、二重/古い/他人の要求|無効候補、漏えい、再接続で引き直し|
|防衛|同じ地形/構成でA/B、順序を入替|拠点張り付きが唯一の正解、移動の余地がない|
|スマホ/UI|844×390/640×360と物理端末で10分|危険が見えない、カード読めない、発熱/フレーム時間悪化|
|保存/負荷|旧セーブとの分離、最大連鎖、実2→4人|旧武器を書換え、端末別ダメージ、処理/配信超過|

試遊5人前後を最初の方向確認に使う案。自発的な再挑戦と理由を記録するが、少数意見を統計的な普遍性やドーパミンの医学的証明にしない。自動botの勝率も楽しさの証拠にしない。

列挙検証はverify-design.py。1系統410状態、3系統7,357状態で候補3種以上と保証枠を確認。抽選分布、戦闘バランス、通信、実機を検証したとは扱わない。

## 実装着手/製品接続の前に必要な判断

推奨試作は旧モードと並存、報酬なし、モード内標準化。今回は設計成果の納品までであり実装を開始しない。

製品化時は（1）既存武器性能の持込か標準化か、（2）旧モード併存か主モード置換か、（3）解放/報酬を既存進行へどう接続するかを具体案で判断する。これらの未決を理由に共同設計自体を未完了とはしない。
