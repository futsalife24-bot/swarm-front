## 依頼と境界

ユーザーは「スワフロをベースに地球防衛軍×ヴァンサバでリビルド」「Opus5.5と協力して一緒に設計」を希望。前段では大群撃破の爽快感、3択強化、日替わり防衛を発展させた別モードを検討。今回の成果物は共同設計であり、既存ゲームの置換・セーブ移行・課金・公開の実行ではない。

## 既存資産と制約（実コードを確認した事実）

- Three.jsの横画面TPS。手動射撃、回避、装填、武器2本切替。12武器種・6系統。兵士、複数マップ、HARROW/CALYXなどの大型敵、音声、当たり判定を再利用できる候補。
- ソロと権威サーバーがsrc/sharedの戦闘規則を共有。最大4人、入力20Hz、状態配信10Hz。共通設定の敵上限40、イベント上限160。これらは確認済み設定値であり、全場面での最大数や性能保証ではない。配信には64KiB制約がある。
- 日替わり武器庫防衛はソロ限定180秒、武器庫HP2000、専用生成処理は生存敵24体以上で新規生成を待つ。1日1回、開始保証/回収武器は保持、勝利追加報酬は拠点残HP依存。クラウドの参加台帳と結び付く。
- 既存の武器庫、育成、レア度、所持武器、クラウド同期、中断再開を破壊しない。既存日替わりの参加台帳を新モードに流用しない。
- 最新バランス比較T7は人間の楽しさを証明していない。武器の単純な火力均一化は行っていない。
- UIは既存テーマ/構成を基礎に、横画面844x390と狭幅640x360で検討する。数百体表示やスマホ高FPSは未検証。

## 体験の柱

1. 自分が狙って道を開く: 自動攻撃が画面を埋めても、優先敵への手動射撃・回避・位置取りが勝敗に効く。
2. 選択が見える形で効く: 最初の30〜45秒で効果を体験し、中盤で構成が化け、完成後に十分使える。
3. 強くなった実感を奪わない: 強化取得直後に敵HPを同率上昇させない。圧倒できる区間と戦術が要る区間を交互に作る。
4. 何度も構成を試せる: 日次回数制限を新モードの基本にせず、終了後に即再挑戦できる。

## 推奨する遊びの骨格（未決の初期仮説）

主モード候補は1回8〜10分の出撃。短い5〜7分案と比較する。プレイヤー操作は現行TPSを残す。手動の主武器と副武器2本、追加の自動支援最大2枠。兵科の新規制作は初期試作から外す。
防衛はリビルドの最初の検証ステージ。完成版は防衛だけに固定せず、戦域の制圧/前進/大型討伐を同じ成長規則で作れる設計を目指す。ただし複数目的を初回試作で同時実装しない。

出撃準備 → 初期の方向性3択 → 戦闘 → 部隊共通XPで強化権獲得 → 各自3択 → 中ボス → 構成進化 → 圧倒区間 → 最終ボス → 戦果/再挑戦。
時間切れや雑魚掃討待ちで終わり方が曖昧にならないよう、最終ボス撃破を明確な勝利条件にする。防衛の拠点破壊/全滅は敗北。

## 3択・成長の草案

- 1出撃で初期選択含む8回前後。強化は一時的なRunBuildへ保存し、元の所持武器は書き換えない。
- スカラー値だけでなく、射撃/装填/回避/撃破/支援に新しい作用を加えるカードを中心にする。
- 手持ち構成に有効な候補だけを抽選。候補全体から単純な無作為抽選をしない。強化継続の選択肢と方向転換の選択肢を出すが、完全な固定レシピゲームにしない。
- 進化は条件を事前表示。装備中の系統カードを一定数取得すると、選択肢に進化カードを保証して提示する案。自動進化と選択進化を比較したい。
- 少数回の無料再抽選。未所有武器専用/上限到達/効果無効の候補を除く。不成立時の汎用候補を用意する。
- 稼いだXPを拾うために戦闘後の掃除を要求しない。隊員全員に共有XP、近距離は吸引、区間終了で残り回収。個人ラストヒット争いは作らない。
- ソロは選択中停止。協力では個人レベルアップで全員停止させず、共通の強化タイミング/安全な区間で選ぶ案。具体的な同期方法と途中切断時の自動選択はOpusと詰める。

## 試作候補の3構成

|構成|主な連携|操作を残す理由|
|---|---|---|
|連鎖爆発|主射撃で撃破→爆発→破片→限定した二次爆発|最初に倒す敵と密度を選ぶ|
|貫通/跳弾|主弾の貫通→別対象へ跳弾→弱点命中で追加効果|射線/弱点/密集を狙う|
|回避/迎撃|回避跡の地雷→起爆で支援回転→装填中を援護|回避経路と装填のタイミングを選ぶ|

進化後も無限再帰は認めない。攻撃起源、二次効果深度、対象重複、クールダウン、総発動数を制限する。敵数を超える見た目の弾数は演出と当たり判定を分離するが、存在しない命中を表示しない。

## 圧倒感の設計

大型敵のスケール、複数方向からの接近、予兆、撃破の連鎖、短い間隔での補充により大群の圧を作る。最初は既存上限内で成立を確かめる。必要なら敵LOD/共有幾何/空間分割/配信差分化を個別に検証して上限拡張を判断する。
主武器の狙い、敵の予兆、足元の危険、味方ダウンを視覚的な最優先層とする。味方エフェクトの省略設定は戦闘判定を変えない。
進化直後に短い爽快区間を配置する。手応え、音、短い視覚強調を用い、報酬待ちアニメや日次圧力で継続を強制しない。

## 持込・永続成長・既存進行

選択肢A: 所持武器性能をそのまま持込（既存育成を活かすが差が大きい）。B: 武器種/好みだけ持込、数値を新モード内で標準化（構成の面白さを比較しやすいが既存の収集価値と分離が必要）。推奨は試作B、製品版はユーザー判断。既存武器の値を変えるという意味ではない。
永続成長は新しいカードや初期装備の選択肢開放を中心にし、永久火力上昇の反復を初期設計の前提にしない。報酬を既存武器庫へ大量供給する案は保留。
日替わりは新成長モードの共通seed/編成を変えた遊び方へ発展可能。現在の1日1回報酬は保存する。新モードの回数無制限と既存の報酬台帳を分離する。

## 技術境界（案）

RunConfig / RunState / RunBuild / UpgradeCatalog / UpgradeOffer / RewardReceiptを分離。既存武器の基礎値→ラン内修飾→戦闘派生値の順に解決。
サーバーが抽選seed、候補、選択回数、選択有効性、戦闘効果、結果を決定。クライアントは候補IDと選択IDを送るだけ。協力の再接続時は確定済み候補/選択/進化を復元し、再抽選できないようにする。
ソロと協力で同じRun規則を実行。Run保存はバージョンを持ち既存保存と別領域にする。旧データ自動変換/上書きはこの企画段階で行わない。

## 段階と判定

P0 設計: 操作、尺、持込、3択同期、既存モードとの関係を決める。
P1 戦闘試作: 1マップ/既存兵士1人/3武器系統/12カード/3進化/既存大型1体。仮UIで人間が試す。
P2 操作とUI: 横画面2サイズ、カード比較/装備連携/進化条件、即再挑戦。実機で10分継続しFPS/入力/発熱/危険視認を確認。
P3 協力: 2人で候補選択/同期/切断復帰/二重報酬防止、次に4人。敵上限と通信性能を測り成立条件を決める。
P4 進行統合: 製品仕様を承認後に入口/報酬/保存を統合。旧モードを残すか主モードへ置換するかは別の決定。

受入の目安（実測前）: 最初の1分で強化差が分かる、各構成で少なくとも1回は明確な相乗効果を経験、進化後に60秒以上操作できる、入力して狙う方が主要脅威へ対処しやすい、異なる構成で再挑戦したい理由を本人が説明できる。少人数の試遊を統計的な普遍性と混同しない。

## Opusへ特に求める反証

防衛固定による棒立ち化、手動照準と強化選択の負荷、8回の3択でテンポが止まる問題、自動支援が主武器を奪う問題、持込標準化の不満、4人の待ち時間、完成した構成を使う前に終了する問題。推奨を変えてよいので、理由/代案/最小実験を具体化してほしい。
