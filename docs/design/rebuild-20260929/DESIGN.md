# SWARM FRONT リビルド共同設計 v1

2026-09-29。CodexとClaudeのUI表示「Opus 5.5 / 高」による共同検討を統合した**推奨設計**。ゲーム実装・試遊・ユーザーの製品仕様承認は未実施。応答APIのモデルIDはブラウザから取得できず未確認。[検討記録](COLLABORATION-RECORD.md)と[採否・試遊条件](DECISIONS-AND-TESTS.md)を参照。

## 1. 結論

**狙って撃った一発が連鎖の起点になり、選んだ強化で群れに道を開く、約7分のTPSサバイバー。**

スワフロの手動射撃・回避・装填・武器2本切替を残す。出撃中の3択で命中・撃破・装填・回避に作用を追加し、同じ系統の3枚で進化する。既存地形で成長ループを検証し、続けて日替わり防衛を発展させた防衛ルールを比較する。既存のタイトル・テーマ・武器行・素材を継承する。

最優先は**誘爆核→導火→連鎖崩落で、手動の一発から群れを崩す瞬間**。カード数や敵数を増やす前に、この体験を操作できる形にする。

## 2. 1出撃の流れ

約7分は戦闘時間の目標。選択・ロードは別計測し、ボスの撃破速度でも実時間は変わる。初期1回＋XPで得る追加最大6回＝計最大7回の3択。進化は追加の選択回数に数えない。7回取得や4:30までの進化は検証目標で、XP不足・分散選択・敗北でも保証する仕様ではない。

|戦闘時刻の目安|体験|強化/選択|
|---|---|---|
|開始前|武器2本と最初の方向を選ぶ|初期3択が系統カード1枚目を兼ねる|
|0:00〜0:30|最初の能力が目に見えて効く|早いXP到達を狙う|
|0:30 / 1:15|射撃が連鎖へ変わる|取得権があれば共通選択|
|2:00 / 2:45|精鋭と群れで射線/回避を使う|系統を伸ばすか別系統へ広げる|
|3:30 / 4:15|構成を完成させる|同系統3枚で自動進化。残り1枚の提示保証|
|4:30〜5:45|進化を使って群れを圧倒|敵HPを強化取得に追従上昇させない|
|5:45・ボス出現直前|最終補給|XP回収と権利更新の後に未処理権利を選ぶ。権利なしなら停止なし|
|5:45〜約7:00|既存大型との決戦|ボス撃破で勝利。ボス中の選択停止なし|
|終了後|構成・進化・最大連鎖を短く表示|同じ装備/別構成で再挑戦|

中ボス戦は初期の必須要件にせず、中型/精鋭で中盤の脅威を作り、既存大型1体を最後に使う。ボス長期化の試作上限は戦闘9:00で任務失敗を仮置き、残り60秒から明示。製品値は試遊で調整する。

敗北は全滅/時間切れ、防衛比較では拠点破壊を追加。進化後の操作可能時間60秒以上を測る。早期撃破できる熟練者を待たせるための固定無敵時間は作らない。

## 3. 3択と進化

- 系統カードは各1回取得。初期3択は3系統版では各系統の入口1枚ずつ。1系統試作ではその系統3枚。各カードは単独でも有効にする。
- 追加選択は異なるカードIDを3枚提示。未対応装備、取得済みの一度限りカード、段階上限、無効な効果は除外する。
- 同系統2枚を持つなら未取得の3枚目を以後毎回提示。見送りは可能。複数系統が該当すれば全系統の保証枠を優先する。
- 同系統1枚なら可能な範囲で続き1枠、残りは別系統/汎用。3枚目の保証枠を優先する。
- 同系統3枚で追加能力が自動解放。操作・既得能力を失わない。初期から必要枚数と進化効果を表示する。
- 3系統版は3+3+1による最大2進化を許す。最小試作は最大1進化。汎用は進化条件に数えない。
- 再抽選は追加選択に出撃合計2回を仮置き。保証枠は維持。新しい候補組を作れなければ無効化し回数を消費しない。
- 既定候補は「進化完成→初期系統の続き→残りのカードID順」の固定順で、抽選時に本人へ表示。「相性が良い」を未定義のAI判定にしない。

最小試作は系統3枚＋汎用3種類＋自動進化1つ。汎用は各最大4段階。7取得までの全経路で3候補が残ることを[列挙検証](verify-design.py)する。回復だけなど状態次第で無意味になる候補は使わない。

汎用案は「装甲補強: 最大HPを基準値の5%ずつ追加」「整備手順: 装填時間を基準値から5%ずつ短縮、4段階で20%」「拡張弾倉: 各段階で基準弾倉の10%を整数切上げ（最低1発）した固定量を加算」。初回は弾倉/装填を持つ対応武器だけを使う。HP補強時は最大値差だけ現在HPも増やす。仮値でありバランス確定ではない。

3系統版は系統9枚＋汎用3種類（各4段階）＋自動進化3つ。橋渡しカードは基本3系統の試遊後に追加検討する。

## 4. 試す3構成

名称・回数は仮仕様。連続命中は引き金1回につき同じ対象へ最大1、手動起源だけを数える。散弾で即完成させず、武器ごとの頻度を実測する。弱点判定への依存は初回必須にしない。

|系統|カード1|カード2|カード3|自動進化と見せ場|
|---|---|---|---|---|
|連鎖爆発|誘爆核: 手動撃破で小爆発|導火: 手動命中で印、次の手動命中で消費起爆。誘爆核の爆発でも印を付ける|圧縮炸薬: 同じ敵へ3回の手動命中で小爆発。既存爆発と重なる場合は半径を拡張し二重発動なし|連鎖崩落: 手動で印を起爆すると近くの印へ伝播、深度2まで。最初に狙う敵で崩れ方が変わる|
|貫通/跳弾|徹甲芯: 手動弾の貫通対象+1|反射弾: 同じ敵へ3回の手動命中で近くの別対象へ1回跳弾|整列射: 貫通対象+1。1発で3体以上に当てると弾倉へ1発返す、1射1回|串刺し: 跳弾撃破で次の手動弾へ貫通+1と追加威力。無限返弾/再跳弾は不可|
|回避/迎撃|残像地雷: 回避終了地点に地雷、最大3。4個目は最古を消して置換、消去起爆なし|戦術装填: 回避後の次の装填を短縮。既存回避クールダウンに従う|迎撃子機: 手動命中で1チャージ。弾を消費した装填中のみチャージを使い短い迎撃1回。地雷起爆でもチャージ可|反撃線: 地雷起爆でチャージ、次の手動命中で追加迎撃弾。常駐子機/三角形継続ダメージなし|

迎撃チャージは上限1、同時成立でも重複加算なし。同じ起点の連鎖は同じ対象に同じ効果を1回だけ与え、地雷の多重起爆も起点IDで制限する。空撃ち装填/回避連打だけで主火力を無限生成するループを検証する。射撃を補う短時間の自動狙いは許すが、常時自律攻撃2枠は初回に採らない。

## 5. 共有XPと協力選択

最終目標1〜4人、検証はソロ→実2人→4人。XPは部隊共有で同じ取得権、候補/構成は個人別。ラストヒット争いをなくし、近距離吸引と補給境界の残りXP回収で拾い残しを減らす。

初期を除くXP閾値は6段階。取得権は累計最大6、未使用権利も最大6保持。XP値は敵編成と対にした試作データで調整し、取得数/不足量を計測する。5:45の最終補給でXP回収と権利更新を済ませ、その後は新しい権利を発行しない。最終補給の確定直後にボスを出し、間にXPを稼げる戦闘時間を挟まない。ボス中のXPは戦果表示のみに計上し、未使用の強化権として見せない。

共通境界は時刻で到来し残敵ゼロを待たない。「XP回収→権利更新→候補生成→共通停止」。権利が誰にもなければスキップ。停止中は敵、弾、継続ダメージ、回復、クールダウン、作戦時計を全部停止。残敵/弾はその場に残し、再開後へ持ち越す。

ソロは無制限選択。協力は**停止全体で最大15秒**、全員の全権利処理完了で即再開。複数権利は1枚ずつ確定し、新しい構成から次候補を生成する。期限時は残りも同じ既定規則で順に確定。1枚選んだだけで残権利のある人を完了扱いしない。

切断者も同じ期限/既定選択。復帰時は未確定なら同じ候補、確定後なら確定構成。再接続で再抽選回数を増やさない。候補の到着が遅れて読めない場合を計測し、期限/回数は通信試験で再判断する。

戦場を背後に暗く表示し危険位置を確認できる。確定後は射撃入力の押しっぱなしをリセットし短い再開予告。停止合計、最後の人による待ち、予告時間を別計測する。15秒×6回なら90秒、初期選択は別なので「実所要7分」と宣伝しない。

## 6. 日替わり防衛の発展

P1は拠点なし生存＋ボス。P2は同じ地形・カード・敵役割で拠点を追加し、前に出る/戻って守る判断が増えるか比較。慣れの影響を避け、試遊者ごとにA→B/B→Aを入れ替える。

製品の推奨は、繰り返せる「迎撃作戦」と同じ戦闘規則の「日替わり作戦」。後者は地形/侵攻方向/支給系統を固定し、普段選ばない構成を試す枠にする。ランキングや新報酬経済は最初に作らない。

既存の日替わり180秒・1日1回・保証武器・参加台帳は別管理で保持。新しい名前/導線、旧モードとの統合/主モード化は製品判断。試作で旧台帳を書き換えない。

## 7. UIと撃破の気持ちよさ

- 横3枚、名前・発動条件・変化・連携・進化までの枚数を1画面で比較。必須説明を詳細へ隠さない。
- 確定→初発動→進化→大群撃破で異なる短い音/視覚反応。進化で長く操作を奪わない。
- 連鎖数と自分の一発が起点であることを見せる。存在しない敵/命中/撃破を水増ししない。
- 敵予兆・照準・足元・味方ダウンを最優先。味方エフェクトの減量で戦闘判定を変えない。
- 既存UIを土台に844×390と640×360、実スマホで確認。カード選択と射撃の同時操作を要求しない。
- 大群感は密度、撃破数/分、補充間隔、巨大敵とのスケール差で測る。進入口と予兆を使い、背後の至近距離に突然湧かせない。

現行設定は敵40/イベント160、日替わり専用生成は生存24以上で待機。性能保証ではない。既存制約内で試し、不足ならLOD/空間分割/通信量を測って拡張する。

## 8. 既存資産と報酬

試作は対応武器種/見た目だけ持ち込み、モード内基礎値を標準化。元の所持品・レア度・強化値は変更しない。試作報酬なし。Runの一時状態を独立領域に持ち、旧セーブを自動移行しない。

恒久進行の推奨は新しい選択肢の解放。収集価値を候補追加/外見へ反映する案はあるが、所有者の火力を無断で置換しない。持込標準化の正式採用、報酬、旧進行との接続は別の承認事項。

## 9. 技術境界

|データ|内容|権威/配信|
|---|---|---|
|RunConfig|ルール版、地形、難易度、人数、敵編成、XP閾値|サーバー決定、公開|
|RunPublicState|フェーズ、時計、共有XP、確定構成/revision、進化|サーバー決定、全員|
|RunServerState|抽選seed/RNG内部状態|サーバー専用、本人を含めクライアントへ送信しない|
|RunPrivateState|本人の候補、世代、再抽選残数、既定候補|サーバー保持、必要項目を本人のみへ|
|UpgradeCatalog|対応条件、効果、上限、説明、進化条件|バージョン一致|
|RewardReceipt|将来のrun/player/受領状態|試作は付与なし。接続前に冪等性検証|

既存prepareStateはWorldを展開して共通配信するため非公開候補/RNGをWorldへ直置きしない。送信状態を明示選択する。入力20Hz/配信10Hz/64KiB制約内で測定する。

選択要求はrun ID、offer ID、revision、card ID、request IDを照合。古い/他人の候補、期限後、二重再抽選を拒否し、再送は同じ結果。構成revisionで装備キャッシュ/再接続を同期。戦闘時計と壁時計期限は分離する。

効果は手動命中/撃破/装填/回避へ接続し、起源、対象、1射ID、深度、発動間隔、更新予算を持つ。許可した二次連携だけ発動。ダメージ上限はルールで決め、端末の描画省略でダメージを変えない。各命中経路の接続箇所は実装時に再確認する。
