## 1. 一文コンセプト

自分で狙って大群に突破口を作り、出撃中の3択で武器と支援を進化させ、完成した構成で巨大な敵を倒す、短時間の協力TPS。

「地球防衛軍×ヴァンサバ」というユーザーの方向を、大群/巨大敵/兵士操作と、3択/組合せ/出撃内成長へ分解した案。作品の外見や名称はスワフロを継承する。
最初の検証には日替わり防衛の地形と敵生成を利用するが、完成版を1日1回の防衛だけに限定しない。

## 2. 何を残し、何を作り直すか

|領域|推奨案|理由|
|---|---|---|
|基本操作|横画面TPS、手動射撃、回避、装填、2本の武器切替を残す|重要な敵へ自分で対応する気持ちよさ|
|自動攻撃|ラン内で得る支援最大2枠に限定して試す|兵士操作を補い、大群への処理力を増やす|
|成長|出撃中の3択と進化を追加。終了後にラン内強化をリセット|毎回違う構成を試す|
|敵|既存の通常/飛行/遠距離/大型の役割を活かす|物量だけでなく対処の順序が生まれる|
|戦場|防衛1面で試し、その後は制圧/前進/討伐へ拡張可能にする|固定地点で撃つだけになるのを防ぐ|
|アセット|既存モデル、マップ、音声、武器の外見を再利用|最初から素材を全面制作し直さない|
|恒久進行|新しい選択肢の解放を中心に提案|永続火力の積上げがラン内成長を消さないようにする|
|既存セーブ|保持。新モードの一時強化を既存武器へ書き込まない|収集済み資産を守る|
|日替わり|通常は何度でも挑戦。日替わりは固定条件の挑戦枠を別途検討|やり直して構成を試せる|

今回の依頼は設計。上表は実装済みでもユーザー承認済み仕様でもない。

## 3. 1プレイの流れ

製品の目標は所要8〜10分程度。戦闘時間、選択時間、ロード時間を別々に計測し、時間保証として扱わない。初期選択を含む7〜8回の選択を比較する。

1. 出撃準備: 武器2本を選び、3択で最初の強化方針を選ぶ。
2. 最初の30〜45秒: 最初の強化が何を変えるか分かる敵編成。次の強化権を早めに得る。
3. 前半: 群れを処理し、XPを集める。射線・回避・武器切替を使う異なる脅威を混ぜる。
4. 中盤: 2〜3枚の連携が成立。中型/精鋭への対応と構成の方向を選ぶ。
5. 終盤前: 進化を獲得し、同じ通常敵を大幅に処理しやすくなる区間を設ける。
6. 最後: 予兆と隙を持つ大型敵を倒す。強化した火力だけでなく、回避/優先目標を選ぶ操作も使う。
7. 戦果: 構成、進化、象徴的な出来事を短く表示し、同じ装備/別装備で再挑戦。

大型敵を倒すと勝利。防衛試作では拠点破壊または全滅が敗北。ボスの無制限長期化を防ぐ上限/敗北予兆は試遊で決める。大型出現時刻だけを1プレイの終了時刻と呼ばない。
進化後に少なくとも60秒程度は操作できる目安を置く。早期撃破可能な熟練者を待ち時間で拘束しない。

## 4. 3択の設計

- 攻撃の仕組みが変わるカードを中心にする。「攻撃力+数%」だけの候補を並べない。
- 現在の装備/構成に有効なカードだけを出す。未装備専用、上限済み、無効な組合せは候補から除く。
- 既存構成を伸ばす選択と、違う連携を始める選択が共存するよう抽選する。毎回同じ3枚を出すという意味ではない。
- 進化の条件と効果を先に見せる。条件達成後は進化を候補に保証して提示し、選択で取得する案を推奨。自動進化案とは試作で比較。
- 再抽選は出撃あたり少数回無料。回数と候補は保存し、再接続で増やさない。
- 候補が3つ揃わない場合の有効な汎用カードを設ける。同じカードの複製や無効なカードで穴埋めしない。
- 強化後に敵能力を追従上昇させない。敵出現計画と難易度は出撃条件に基づき、選択を無意味にしない。

### 試作の3構成

|構成|基礎効果|連携|進化時の変化|兵士操作の意味|
|---|---|---|---|---|
|爆発|主射撃で倒した敵が小爆発|爆発で倒した敵から破片|限定回数の二次爆発で群れへ広がる|最初に倒す敵と密集を狙う|
|貫通/跳弾|主弾が複数の敵を貫く|貫通後に近くの別敵へ跳ねる|条件を満たした弾に限定分裂|射線と弱点を狙う|
|回避/迎撃|回避跡に地雷を残す|地雷の撃破で支援の再使用を短縮|回避と装填の隙を迎撃が補う|敵を引きつける経路とタイミング|

3構成×4枚を仮のカード制作量とする。ただしすべての組合せが等しく成立する保証はない。有効候補が不足する場合、汎用カードを追加するか試作の選択回数を減らす。枚数を優先して無効な3択を作らない。
複数のカードが同じ攻撃へ作用する順序を固定する。例: 基礎弾→貫通/跳弾→命中→主攻撃による撃破→撃破時効果。二次効果が再び同じ撃破時効果を無限に起こさないようにする。

## 5. 協力中の成長と選択

目標人数は1〜4人。共有XPで部隊全員が同じ回数の選択権を得て、カード内容は各自が決める。ラストヒットや回復役への偏りで成長差を作らない。

初期推奨は「区間間の共通停止」。個人のレベルアップのたびに全員を止める方式は採らない。ソロも同じ区間ルールを基準とし、ソロだけ即時選択する案は比較対象に留める。

- 戦闘中はXP到達と次の強化機会を短く通知するだけ。
- 区間境界で全員を同じ強化フェーズへ移す。敵/弾/継続ダメージ/回復/クールダウン/作戦時計を一貫して停止する。壁時計の通信期限は別に管理。
- ソロの選択は時間制限なし。協力は全員確定で即再開、未確定時は20秒を仮上限として試す。
- 締切時は事前に表示した有効な既定候補を選ぶ。切断者にも同じ規則を使い、復帰時に確定済みカードを知らせる。
- 区間境界は残敵ゼロのみを条件にしない。取り残した飛行敵が選択を永遠に遅らせないよう、有限の終了条件を設ける。
- 区間終了で残敵を消す案、次区間へ持ち越す案の体験差は未決。これを曖昧なまま実装へ渡さない。

20秒と選択回数は人間2人で待ち時間を測って決める。選択中だけ無敵になる個別メニューで危険を回避する抜け道は作らない。

## 6. UIと爽快感

カードは横3枚。短い名称、効果の変化、対象装備、現在の連携、進化条件を優先する。選択に必須の説明をスクロールの先へ隠さない。
既存のテーマと入口を継承し、844×390と640×360で比較する。演出の優先順位は敵の予兆/照準/足元/味方ダウンが最上位。自分の強化演出、味方の強化演出の順に密度を調整する。
大群感は同時数だけでなく、複数方向の接近、巨大敵とのスケール差、群れを割る射線、短時間の連続撃破で作る。ゲームに存在しない当たり判定や撃破を演出だけで水増ししない。
カード決定、初発動、進化、大群一掃で音と視覚の反応を区別する。数値上昇だけで成長を伝えない。

## 7. 持込・報酬・旧モード

推奨は、試作では既存武器の種類/見た目を選び、モード内の基礎値を揃える。所持品原本の性能を下げたり上書きしたりしない。
製品で標準化を採用するか、既存のレア度/個体差を持ち込むかはユーザー判断。前者は構成の楽しさを比べやすく、後者は既存の収集価値を活かしやすい。
新モードの強化は出撃終了で消える。恒久解放は新しいカード/初期選択肢などを候補とし、未解放が多い初期プレイヤーにも成立する基本構成を用意する。
既存日替わりの参加権、保証武器、回収済み報酬は変更しない。新モードの繰返し報酬を既存台帳へ直接追加しない。
新モードを本編に置き換えるか、並存して検証後に主モード化するかは別決定。推奨は並存試作→比較→主モード化判断。

## 8. 実装時の技術設計

### データの分離

- RunConfig: ルール版、ステージ、難易度、開始条件、人数。
- RunPublicState: フェーズ、時計、共有XP、各人の確定済み構成、進化、公開戦闘状態。
- RunPrivateState: 抽選器の状態、各人の候補、選択世代、再抽選残数、未確定要求。サーバー内と対象本人への限定配信。
- UpgradeCatalog: 効果定義、対象条件、前提/上限/進化条件、説明のデータ。
- RewardReceipt: run ID、player ID、受領状態と一度だけ適用する報酬。

既存prepareStateはWorldの大部分を展開して共通配信するため、非公開候補や抽選情報をそのままWorldへ追加しない。送信する状態は明示的に選ぶ。
既存encodeStateの丸めや装備キャッシュがラン内修飾の正確さを壊さないよう、確定構成のrevisionを別途同期する。確定済み武器原本と一時修飾を分離する。

### 権威と再接続

候補/発動/進化/結果の権威はサーバー。選択要求はrun ID、offer ID、revision、card ID、request IDで識別し、再送は冪等にする。古い候補、他人の候補、締切後、未解放、不正な再抽選を拒否。
候補表示中に切断しても同じ候補/確定結果へ復帰させる。乱数を振り直さない。選択締切と通信復帰期限を同一の時計で扱わない。
ソロと協力で共通Run規則を実行する。新しいRun保存は独立バージョンを持ち、旧セーブのコピーを破壊しない。

### 発動と負荷

攻撃起源、連鎖深度、対象重複、発動間隔、1更新あたりの処理予算を設ける。二次効果は許可された連携だけを起こす。処理予算で演出だけが落ちた場合と、戦闘ルール上の発動上限を区別し、端末性能でダメージを変えない。
最初は既存の敵/通信上限内で測る。大群に必要な密度が成立しない場合は、描画LOD/空間分割/効果再利用/配信量を検証して拡張を判断する。現行40という設定値を性能保証や全ケースの敵数として使わない。

|協力|実2人、その後4人|選択待ち、切断復帰、確定構成同期、共有XP、報酬重複防止が成立|

初回から新兵科、数十のカード、建築、大規模地形破壊、ランキング、無限モードを同時に追加しない。まず出撃1回で「自分で戦う」と「構成が化ける」が両立するかを確かめる。
数値の最適化より先に、主操作の意味、棒立ち化、無効3択、進化前終了、協力待ちを人間の試遊で確認する。自動botの勝率を楽しさの証明にしない。
