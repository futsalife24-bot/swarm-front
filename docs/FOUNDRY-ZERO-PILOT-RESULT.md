# FOUNDRY ZERO導入に伴うテストpilotの探索・壁回避修正

2026-09-12。branch `codex/home-armory`、base/HEAD `4186f25f7c9695f95ea897ad182db5f85fac3091` 上の未コミット変更。実装対象は `tests/bot.ts`。独立shared監査の記録とは分けた、テスト補助コードの実装・自己検証記録である。

## 問題と根拠

ST20の既存クリア試験が600秒・265kills・wave4で時間切れになった。現在のsharedと既存pilotをVite SSRで読み込み、通常の `step(w, { p: pilot(w, "p") })` だけで同じ失敗を再現した。

wave3は217.70秒に開始し、ボスが全滅したのは542.50秒。wave3の328.85秒中、231.00秒はpilotが敵を選べず `fire=false` だった。300〜390秒にはFOUNDRY 1体だけが残り、外周x約±80を巡回していた一方、pilotはx=0の中央通路を往復していた。wave4開始は546.55秒となり、通常敵の掃討時間が不足した。

旧pilotは敵を60m以内・見通しがあるものに絞り、屋外で候補がなくなると敵の位置と関係なく中央通路を往復した。地上FOUNDRYの外周巡回に対して、探索へ移れないことが原因だった。少なくともこの失敗再現は、敵AIの停止や600秒の仕様不整合を示していない。

## 変更

敵を見失った屋外では、最寄りの生存部位へ向かう地上経路の次の角を取り、0.5秒ごと・角への到着時に更新して歩く。既存 `foundryPath` の広い4.2mクリアランスを、プレイヤーの探索には保守的な経路として再利用した。標的を再捕捉したら探索用waypointを破棄して従来の戦闘操作へ戻る。

返すものは従来どおり通常の移動・照準Inputだけ。60mの照準選択、合法装備、時間制限、敵数・HP、wave完了条件は変えていない。worldの座標・HP・報酬を直接変更する処理は追加していない。

## 検証

探索修正直後の `npx vitest run tests/stages.test.ts -t 'completes within the time limit'` は終了コード0。既存の全20stageクリア試験が20/20成功し、当該コマンドの対象外10件はskip、実行時間15.84秒だった。

## 曲率修正後に検出した壁への回避

shared側の最終曲率修正後、主担当の全suiteでST16が131.5秒・75kills・HP0となった。限定再現も一致した。洞窟の袋小路で125〜131秒の多くのtickが移動距離0で、レーザーへの `dodge=true` と `evade>0` がある時にも止まっていた。例として131.05秒にp=(67.005,80.124)、evade=0.12、dodge=true、移動距離0、131.45秒に同座標でHP0となった。

既存pilotは接近弾を検出していたが、戦闘中の移動方向が壁で塞がれた際に代替方向を選んでいなかった。回避の有効時間が終わったあとも同じ位置へ連続射撃を受けていた。

修正は `tests/bot.ts` の戦闘移動に限定した。現在の進路をコピー上の通常 `move` で0.25秒分予測し、壁による移動量の不足が25%を超える場合だけ周囲の方向を試す。進みたい向きへの進捗と実移動量で、通れる方向へInputを向ける。予測中の `move` はコピーだけに作用し、world内のプレイヤーは `step` に渡した通常Inputでのみ移動する。既存の接近弾判定・evadeの時間と再使用間隔は変更していない。
