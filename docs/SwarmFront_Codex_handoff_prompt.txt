SwarmFront — 初期試遊版を実装する際のCodex向け依頼文

【使い方】
この文面は、ユーザーが実装を依頼するときに、
「SwarmFront_grilling_playtest_spec_v1.md」と一緒に渡すためのテンプレートです。
仕様検討チャットから、自動的にコード変更・セーブ削除・公開を許可するものではありません。

【目的】
添付の統合仕様を基準に、まずST1〜3の通常・中難易度＋3-Aで、
実際に試遊できる一連のゲームループを実装してください。
数値の細かな質問を続けて試遊を遅らせず、採用済みの暫定値はそのまま出発点にしてください。

【最初に確認】
1. 実際のリポジトリ、適用されるAGENTS等、現在のgame/docs/PROGRESSION.md、既存差分を確認。
2. 添付仕様の「確定」「暫定」「実装時に仮置き」「後続」を区別。
3. 既存文書と違う場合は、添付の最新決定を反映する箇所を特定。
4. 兵士モデル・背景等の別作業は保護。無関係な差分の削除・巻き戻し・上書きをしない。

【今回の重要な最終決定】
・通常武器所持枠は現行の2倍を暫定採用。実数はコードから確認する。
・所持上限超過品は、獲得報酬を失わないための一時保存だけにする。
・超過が残っている間は次の出撃不可。整理して通常枠に収まれば出撃可能。
・超過品を自動廃棄・自動解体しない。通常品を待機へ逃がして装備制限を回避しない。
・結果画面は性能確認・ロック中心。個別・一括とも解体を置かない。
・武器庫／出撃準備で整理。空きへの自動補充はロック優先、その後入手順。
・全兵士の登録装備とロック品は解体から保護。
・待機があっても出撃可能、という旧提案は実装しない。

【進め方】
・共通処理と必要な小範囲をつなぎ、出撃→戦闘→勝利回収／敗北→報酬→育成→再挑戦を成立させる。
・面別の制限時間、wave間隔、敵数上限、3-Aの座標等は、現行データを調査して仮置きし、設定表に記録する。
・ユーザー承認済みの仮値と、実装者が置いた仮値は別欄にする。
・ST4通常の第4解放素材は、最初の小範囲とは別にテストする。
・初遭遇演出は敵1種類、外観・共有は武器1種類から検証して展開する。
・確認事項が生じたら、真に仕様変更や権限に関わるものだけをまとめて短く質問する。
・最初の動作ゲートに、全数値バランスの最終完成を要求しない。
・通し動作に合格した後、本編20面×2難易度＋3-A×2難易度へ展開して面別検証する。

【今回先回りしないこと】
日替わり武器庫防衛、実広告SDK接続、50面化、最高難易度、協力への新育成・進行の全面適用、
ミッション累計による新コンテンツ解放は後続。
3-Bや、撤回されたスキル・報酬・所持品ルールを復活させない。

【実行境界】
・この依頼を受けた際も、実際の作業環境の権限・承認条件を守る。
・旧セーブ初期化は、控えを作り、必要な確認を得てから。無断で現在の保存を消さない。
・commit / push / merge / 公開 / 課金は、別途の承認範囲を守る。
・テスト用広告は開発・検証用だけ。通常プレイで実広告を見たことにしない。

【報告】
1. 実装した範囲と未実装の範囲。
2. ユーザーが起動・試遊する手順。
3. 添付第23節の受入条件に対応したテスト結果・実画面の証拠・未確認事項。
4. 仮設定表と、プレイで確認してほしい主要な調整点。
5. 保存・既存差分・協力機能に対する保護確認。

テスト未実行の機能、テスト用広告だけの確認、ST1〜3だけの確認を、
全機能・実広告・全20面が完成したかのように報告しないでください。
