# 兵士のその場旋回（足の踏み替え）と他プレイヤーの向き補間 — 2026-10-12

利用者の指摘：「兵士がその場でエイムして回転する姿が機械的」。原因と対応は次のとおり（見た目だけの変更。戦闘判定・入力・通信・保存・モデル・動作クリップの中身は変更しない）。

## 原因

1. 立ち止まって向きを変えるとき、モデル全体が照準の向きへそのまま回り（`render.ts` の `m.rotation.set(0, -yaw, 0)`）、足が地面の上で回転台に乗ったように滑っていた。移動中の腰の追従（`moveYaw`）はあるが、停止中は0.18秒で0へ戻すだけで、足踏みの動作はなかった。
2. 他プレイヤーの兵士の向きは1秒20回の状態更新の値をそのまま使っていたため、回るときに段差が出ていた（1コマで最大0.48ラジアン）。

## 変更

- `src/client/turn-in-place.ts`（新規）：立ち止まっているときの足の向きを管理する小さな状態。
  - ひねりが0.62ラジアン以内なら、足を地面に残して腰をひねる（上半身と照準は今までどおり向きに追従）。
  - それを超えるか、0.22ラジアン以上のひねりを0.75秒続けると、足が踏み替えて追いつく（約0.12秒の追従、最低3ラジアン/秒）。
  - `easeYaw`：他プレイヤーの描画上の向きを約0.06秒で補間する。2.9ラジアンを超える急な反転は補間せずにそのまま反映する。
- `src/client/standard-trooper.ts`：停止中は、既存の `moveYaw`（腰をひねり、背骨で打ち消して照準と両手の握りを保つ仕組み）にこのひねりを入れる。踏み替え中だけ、下半身に既存の `Lower_Walk` の脚を使い、旋回角に応じて0.8周期/ラジアン進める。上半身のクリップ、移動中・回避・装填・持ち替え・被弾・ダウン時の処理は変更なし。足の接地固定（移動用）は踏み替え中は使わない。
- `src/client/render.ts`：他プレイヤーの兵士の描画上の向きを `easeYaw` で補間する。自分の兵士は従来どおりカメラの照準の向きを使う。新しい作戦の開始時と、アニメーションしない描画では補間しない。

## 検証

- 型チェック成功。`npm run build` 成功。
- 新規単体 `tests/turn-in-place.test.ts` 7件成功（小さな向き変えで足が動かない、限界を超えたら踏み替えて揃う、ひねりを続けたら揃える、速い旋回でもひねりが限界＋1フレーム分に収まる、±πをまたぐ、移動からの引き継ぎで段差がない、他プレイヤーの補間と急反転）。
- 全単体：927成功／5失敗＋1スイート読込失敗。失敗はいずれも変更前のmainでも同じ（aim rocket、render 弾位置、maps 晶脈、stages 25、weapon-stat-marks の読込、enemy-report-motion の翼端ミサイル。最後の1件は今回のmain `35125e5` で、修正を外した状態でも同じく失敗することを確認）。
- 実描画の比較（撮影用の検証ページで、本番のRendererと兵士モデルを描画。2人を同じ向きの時系列で操作。自分の兵士p1、他プレイヤーの兵士p2）：
  - ゆっくり1.1ラジアン回す区間：修正前は足ごと回り、足が1コマ約0.05m滑る。修正後は足が動かず（1コマ0.001m以下）、限界を超えたところで1回踏み替える。
  - 止まって保持する区間：修正後は足が完全に静止。
  - p2の向き：修正前は状態更新のたびに最大0.48ラジアンの段差。修正後は0.12→0.30→0.39…→0.001と減っていく連続した変化。
  - 足の「接地中の滑り」の合計：修正前1.95m → 修正後 p2 0.79m、p1 1.57m（p1は0.25秒で2.4ラジアンという急旋回を含み、その区間は素早い連続の踏み替えになる）。
- 未確認：実スマホ、実通信の協力での目視、長時間プレイ、人による自然さの評価。急旋回時の素早い踏み替えは数値上は破綻していないが、見た目の好みは要確認。
