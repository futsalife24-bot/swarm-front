# swarm-front — first playable

2026-09-09: 全20ステージ・6マップ。街区・倉庫・工業区に草原・雪山・分岐洞窟を追加。マップ配置は [MAPS-6.md](docs/MAPS-6.md)、敵編成は [STAGES-20.md](docs/STAGES-20.md) を参照（以下は初期版の説明を含む）。

開発用仮名の、独立した三人称3D協力アクション。市街地「灰明の街区」で3ウェーブを突破し、大型個体クラウンを倒す。初期歩兵1種類、ライフル・ショットガン・ロケット、2本持ち込み。コード生成の兵士・多脚生物・建物・武器・効果音を使用し、他作品の素材を流用していない。

**公開前のローカル版。インターネット経由・Android実機は未検証。本番公開・mergeは独立監査後の承認待ち。**

## 起動

検証環境はWindows（build 26200 / 25H2）、Node 24.14.1、npm 11.11.0、Google Chrome。依存はpackage.jsonとpackage-lock.jsonで固定。

```powershell
npm ci
npm run dev
```

`http://127.0.0.1:5186/` を開く。ソロにはWorkersもログインも不要。

## ホーム画面アプリ

HTTPSで開いたAndroid Chromeでは、初回読み込み後にブラウザのメニューから「ホーム画面に追加」または「アプリをインストール」を選ぶと、横画面のスタンドアロンアプリとして起動できる。対応ブラウザではタイトル画面に「ホーム画面に追加」ボタンも表示される。

PWAは画面本体だけをキャッシュする。読み込み済みのソロ開始画面は短い通信断でも再度開けるが、初回起動、協力ルーム作成・参加、戦闘中の通信にはネットワークが必要。戦闘状態やWebSocketをキャッシュしないため、古い協力状態を表示するものではない。

協力は別のターミナルで起動する。

```powershell
npm run setup:local
npm run server
```

ローカルWorkersは `http://127.0.0.1:8787`。同一Wi-FiのLANプレイテストでは、一人目が「協力プレイ → ルームを作る → 招待リンクを共有」、二人目は届いたリンクを開いて「招待ルームに参加」。準備完了後、ホストが出撃する。最大4人。通常画面に作成キーや接続先は表示せず、開発時に必要な場合だけ「招待コード・接続先を手動設定」を開く。

公開URLでのルーム作成はCloudflare Turnstileの人間確認で行う。作成キーの入力・配布は不要で、参加者には招待リンクだけ渡す。Turnstileの検証用SecretはWorker設定だけに置き、Git、URL、ログ、配布JavaScriptへ出さない。ローカル開発だけは明示的に `npm run setup:local` を実行し、Git除外の `.dev.vars` の作成キーを「接続先を手動設定（開発用）」へ入力する。ローカル以外の通信先にはHTTPSが必要。

TurnstileのSecret未設定・検証不能時は503、確認トークンなし・不正時は401で停止する。OriginはCORSの制限であり認証ではない。発行済みコードの期限付き登録をGateで確認し、偽コードは全体接続数を更新する前に404で拒否する。登録は最大1時間・日跨ぎを含め最大200件。公式資料：[Cloudflare Turnstile](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/)。

Windowsの古いVisual C++ランタイムでworkerdが起動前にクラッシュする場合、公式の新しいMicrosoft Visual C++ x64ランタイムを使用する。この検証環境ではCodexに既存同梱された14.51.36247.0のDLLをworkerdの隣へコピーして解決した。OS全体の更新は完了扱いしていない。

```powershell
npm run setup:windows
```

このコマンドは既存Codexランタイムを本作のnode_modules内にコピーするだけ。npm ci後には再実行が必要。別環境では `scripts/setup-windows.ps1 -RuntimeDirectory <正規Microsoftランタイムのフォルダ>` またはMicrosoft公式インストーラーを使う。DLLのGit登録・配布は行わない。

## スマホの表示・配置設定

出撃準備の「操作ボタンの配置」で移動・射撃・回避・装填・切替・蘇生ボタンをドラッグし、大きさ・濃さを調整して保存できます。キャンセルと初期配置も利用可能。配置は端末内のみ保存され、武器庫とは別形式です。情報欄のある上部には移動できません。新しい画面サイズで操作ボタン同士が重なる場合は標準配置を使い、元の保存は保持します。回避・装填中は円形ゲージと残秒を表示します。

装備とリザルトは一行一武器の一覧。装備画面では系統と並び順を選べます。検証・参考資料は [MOBILE-UI.md](docs/MOBILE-UI.md)。

## 操作とゲームルール

| 操作       | PC                                  | 横持ちスマホ     |
| ---------- | ----------------------------------- | ---------------- |
| 移動       | WASD                                | 左スティック     |
| 照準       | マウス（クリックで固定、Escで解除） | 右側ドラッグ     |
| 射撃       | 左ボタン長押し                      | 射撃ボタン長押し |
| 装填・切替 | R / Q                               | 装填 / 切替      |
| 回避       | Space                               | 回避             |
| 蘇生       | E長押し                             | 蘇生長押し       |

蘇生は3.5m以内・遮蔽物なし・2.5秒の継続操作。協力では作戦終了まで蘇生でき、倒れた隊員は観戦中も放置切断の対象にしない。ソロのダウンは敗北。5秒間被弾しないと毎秒3HP回復、ウェーブ間は45HP回復。初期HP160。回避中0.32秒は無敵、再使用2.2秒。

3ウェーブは規定数（45・55・65体）の出現と全滅後、4秒の明示インターバルで進む。次波開始時だけ45HP回復し、最後の次波でボス1体が出る。固定90秒待ちは廃止。今回の実測はP1検証記録を参照。人間の初見難易度は未評価。10分で作戦終了。協力開始人数に応じて敵HPを `1 + 0.55 × (人数−1)` 倍にする。

ライフルは連射、ショットガンは近距離8発散弾、ロケットは半径6.5mの爆風。手動射撃時に小さな照準補助が働くが、建物の射線判定を共用する。装備画面の設定で感度・音量（0でミュート）・描画解像度を変更できる。解像度を変えても敵数や当たり判定は変えない。

## 戦利品と端末保存

3レア度。威力倍率は標準1.00–1.12、上位1.00–1.24、最上位1.00–1.36。特殊効果は標準／高速装填／最大3体貫通のうち1つ。ロケットには貫通を付けない。全系統がソロでも抽選対象。

撃破時の道中抽選は9%。緑の戦利品へ近づくと各自の未確定品として回収する。勝利で回収品と保証2個を確定。敗北・復帰できない切断・作戦離脱では未確定品を失う。保存済み品は失わない。

武器には一意ID、作戦には一意ID。報酬受領記録と武器IDで二重追加を防ぐ。装備画面では再抽選しない。localStorageのバージョン1形式、所持上限80。上限時は未保存品をリザルトに保持し、装備外の品をユーザー確認の上で整理して再保存できる。保存エラー時は再試行を表示。壊れた保存・未知のバージョンは勝手に初期化・上書きせず、書き出しを案内する。

端末変更、ブラウザデータ削除では引き継げない。クラウド保存も完全な改ざん防止もない。協力の持込武器はサーバーで系統・上限・効果・ID形式を検証するが、端末内で過去に本当に入手したことの証明はしない。

## 構成と通信

- `src/shared/defs.ts`：武器・敵・市街地・各種上限。
- `src/shared/game.ts`：描画に依存しない共通戦闘計算。ソロとWorkersが同じ関数を実行。
- `src/client/`：Three.js描画、独立ポインター入力、WebAudio、通信、保存。
- `server/worker.ts`：SQLite-backed Durable Objects、実WebSocket、サーバー権威、参加制限。
- `server/testing.ts`：隔離されたローカル結合テスト用の初期状態。通常設定・本番ビルドに含めない。公開禁止。

戦闘計算20Hz、入力送信20Hz、状態配信10Hz。毎描画フレームの通信はしない。座標は通信時に小数2桁。敵・他プレイヤーは補間、自分の移動はクライアント予測とサーバー訂正を使用。入力が250ms途切れたら停止。連射間隔、装填、ダメージ、撃破、進行、抽選はサーバーが決定。

招待情報と参加者トークンはそれぞれcrypto.randomUUIDから生成。参加者トークンをURLへ入れない。入力は2KiBまで、接続ごと35メッセージ/秒まで、送信状態は64KiBまで。部屋4人、認証前を含めソケット8本、未認証5秒、装備更新120回/人/部屋。アドレスごと10分に作成10回・接続60回、全体作成100部屋/日。受付処理は直列化。アドレスはハッシュ化して保持。

ルームは最長1時間、ロビーは3分、戦果画面は2分。戦闘で3分間操作なしは切断。空室ではシミュレーション停止、30秒後に一度だけ掃除する。戦闘状態を毎フレーム永続化しない。

同じページで短い通信断が起きた場合、最大5回再接続し30秒以内なら同じ参加者として復帰。ページを再読み込みしても、同じタブでは「進行中の部隊へ戻る」から30秒以内に同じ隊員・HP・弾数・クールダウンへ戻れる。参加者トークンはタブ単位のsessionStorageだけに保存し、URL・画面・状態配信へ入れない。明示退出・復帰拒否では削除する。切断中のHP・装填・各クールダウン・移動・拾得は進まない。接続者が全滅したら切断者の残HPにかかわらず敗北。全員切断時は最後の状態を保存して一時停止する。

サーバー再起動：ロビー・永続化済みリザルトは保存対象。全員切断後の保存済み一時停止状態も復帰対象。戦闘が動いたままの再起動は完全復旧せず、明示的な中断エラーと装備画面への戻り先を表示する。復旧契約の実装テスト範囲は `docs/TESTS.md` を参照。

## 検証

```powershell
npm run typecheck
npm test
npm run server:test
# 通常WorkersとテストWorkersを起動した状態で
npm run test:integration
npm run build
npm run build:pages
npm run server:build
npm run test:e2e
```

E2Eはインストール済みChromeを使う。必要なローカルサーバーはPlaywright設定にも記載。`server:build` はdry-runのみで公開しない。`build:pages` は `/swarm-front/` 配信用。ソロ独立検証は通常Workersを停止して `npm run test:offline`。詳細な実行結果・失敗の履歴・スクリーンショットは `docs/TESTS.md` と `docs/evidence/`。

公開先は <https://swarm-front.melosalife-24.workers.dev>。公開用は `wrangler.production.jsonc` で、画面の静的ファイルと同じWorkerの `/api` に協力通信を載せる。公開ビルドでは接続先を自動的に同一Originの `/api` にするため、友人は招待URLだけを開けばよい。Turnstileの公開Site KeyはWorkerが設定取得用に返し、検証SecretはCloudflare Secretとしてのみ設定する。`npm run server:build:production` は公開せず設定を検証するdry-run。無料枠の見積もりと制約は `docs/FREE-TIER.md`、次の開始地点は `docs/STATE.md`。
