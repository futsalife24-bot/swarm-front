# 材質返却FBXの軸・面対応検証

頭・胴の `models/textured/*/*.fbx.fbx` をBlender 5.2.1で読み取り比較した。原本・キット・ゲーム未変更。全CLIはfactory-startup・disable-autoexec・python-exit-code 1、最終exit 0。

## 判定

**Blender座標の `returns.rotation=[0,0,0]` でよい。** 頭・胴とも軸置換identity、符号+++。分割FBXから材質返却FBXへの90度回転、鏡映は不要。UIでのY90補正を返却FBXへ重ねて適用しない。

面対応は保持される。共通基準であるsegmentation-input GLBの頂点へ最近傍対応すると、頭51,637面・胴49,073面がすべて一致し、追加0・欠落0。分割FBXも同じ共通基準へ全数一致するため、材質工程で面構成が変化していないことを確認した。

## 座標誤差

境界中心合わせ・一様縮尺補正後の分割FBXとの最大双方向頂点距離は頭0.00001534、胴0.00002094（全幅約1）。補正係数は頭0.999997139、胴1.000026196。小さな座標変動は存在し、生の浮動小数点の完全同一ではない。

共通基準GLBとの補正係数は頭/胴とも約0.999511719。最大距離は頭0.00004651、胴0.00005044。各ファイルの中心・軸・縮尺・SHA256を `texture-return-head-comparison.json` と `texture-return-body-comparison.json` に保存。

分割FBXを直接最近傍基準とすると、元からある微小差の重複頂点付近で頭252面・胴111面が厳密な座標キー比較に一致しない。そこで微小差重複のない共通基準GLBへ分割FBXと材質FBXをそれぞれ対応させ、双方の全三角形一致を確認した。単なる面数一致だけで判定していない。

この検証は軸・頂点位置・面対応のみ。材質の見た目、UV品質、修整箇所の完了、リグ品質の合格を意味しない。
