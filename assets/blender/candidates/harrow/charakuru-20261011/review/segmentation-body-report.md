# 胴体分割前後の限定検証

Blender 5.2.1、factory-startup・disable-autoexecで元040 FBX・upload GLB・分割FBXを読み取り比較。原データ未変更。実行exit 0。詳細と対象SHA256は `segmentation-body-comparison.json`。

**upload GLBから分割FBXへの面構成保持を確認。** 軸置換はidentity、符号は+++で追加回転・鏡映不要。合わせる式は `q = (p - Cseg) * 0.9994855359703129 + Cglb`。

- Cseg = (0, 0.00000002980232239, 0.32803550362586975)
- Cglb = (0, 0.00000001490116119, 0.3278808891773224)

補正後の最大双方向頂点差0.0000464275、RMS約0.00001544。全幅約1に対し最大0.00465%。最近傍の元頂点へ対応付けすると**全49,073面一致、追加0・欠落0**。対応位置数も双方26,110。浮動小数点座標の完全同一ではないが、この誤差範囲で面構成・形状を保持する。

|対象|メッシュ|頂点|ポリゴン|三角形|
|---|---:|---:|---:|---:|
|元040 FBX|1|26,110|29,247|49,084|
|upload body.glb|1|26,537|49,073|49,073|
|分割body.fbx|214|26,212|49,073|49,073|

Tripo UIの26,715頂点とFBX読込26,212頂点の差について、UIの集計定義・書出し/インポート処理を確認していないため原因は未確定。UVや法線分割が原因と断定しない。原FBX→GLBの三角分割数には差があるため、元FBXの全表面が数学的に完全同一とする検証ではない。

この判定は分割工程で追加破損や軸変更がないことの限定検証。元候補のミサイル6本・すねアーティファクト等の修整済みを意味せず、材質・リグ・ゲーム統合の合格でもない。
