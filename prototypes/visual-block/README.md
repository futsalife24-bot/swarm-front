# 市街地と兵士の比較試作 — 改善仕上げ版

**現行はv2です。** 布のしわ・ポーチの収まり・持ち替え干渉・影の負荷・歩道接地・横画面操作まで追加改善しました。現行の成果物・検証・制約は [FINISH.md](FINISH.md) を参照してください。入口URLは同じで、改善版Bが最初に開きます。

以下は初版の履歴です。未実施項目・負荷数値はv2の現状を表しません。

現行Three.jsのRenderer、StandardTrooper v7、共有戦闘処理を直接使う、ローカル専用の比較入口。主人公1体と市街地の向かい合う建物2棟を対象にした。元のGLB・骨格・18アニメーション・通常ゲーム入口は変更していない。

## 開き方

gameで `npm.cmd run dev -- --port 5341` を起動し、http://127.0.0.1:5341/prototypes/visual-block/ を開く。

最初は停止状態。A/Bで位置・姿勢・画角を保持して切替。「停止 / 再開」で操作開始。WASD移動、左右矢印で照準方向、Space射撃、R装填、Q武器切替。「同じ位置へ」で初期状態。通常のセーブ・ネットワークには接続しない。戦闘計算を模造した動画やモデル鑑賞画面ではなく、本体のソロ戦闘計算と描画を再利用する比較用入口。HUDと入力UIは比較専用。

## 観察と判断

PPSの14秒・20秒および砂漠参考では、ベストの厚み、布との重なり、肩から銃までのまとまり、背景の中距離構造が効いている。微細模様だけでは差を埋められない。

現行実物は最新v7。古い添付より構えは改善されているが、通常カメラで胴の表面が均一に見え、装備の奥行きが弱い。影は横290m/2048px≒14cm/texel、normalBiasも12cmのため、数cm単位の接触が消えやすい。建物には既に画像テクスチャと窓パネルがあるため、それらを再制作せず、凹凸と影を優先した。

試作B:

- 背面2個・腰2個の丸角ポーチ、背面帯を既存Chest/Pelvisへ追従。独自の単純形状で、PPS素材は使用していない。
- 布を暗く粗く、装甲の反射とセラミックの粗さを別調整。布の本格的なしわ制作は未実施。
- 既存2048px影を76m幅へ集中、normalBiasを1.2cmにし、動作中に更新。自己影も有効化。
- 建物2棟の窓見込み・縦枠・窓台・基壇・角、歩道段差と排水口を追加。材質ごとにまとめ、道路中央へ小物を置かない。
- 遠景のfog終端を950m→600mにし、近景と背景の距離差を調整。
- FOV65°・距離5.2m・オフセット0.8mはA/B共通。敵を見る視野を狭めず、形状と影の効果を切り分けた。

## 検証と証拠

`node scripts/check-visual-block.mjs` でChromeを操作。1280×720 / 844×390の同一停止状態A/B、Aへの復帰、前進約4.91m、射撃32→28発を確認。57骨・18クリップ読込、JS例外なし。画像を目視し、ポーチの追従・走り・構え・背景を確認した。動作速度のPPS完全一致や肩肘の全姿勢での無干渉を合格としたものではない。

証拠は `../../dist-validation/visual-block/`:

- `1280-before.png` / `1280-after.png`、`844-before.png` / `844-after.png`
- `1280-restored.png`、`moving.png`、`firing.png`
- `checks.json`（状態・描画量・短時間計測）、`manifest.json`（成果物のSHA256）

PC短時間測定: 静止はA/Bとも平均約16.68ms。通常描画36→47 draw calls、300,744→306,696三角形。移動中はA/Bとも約16.68msだが、影パス込みで36→73 calls、310,872→556,192三角形。毎フレームの影更新が主な追加負荷。垂直同期・2秒程度の短時間測定であり、余力やGPU時間を示さない。40敵・長時間・実スマホ・発熱・タッチ操作は未検証。モバイル60fpsを保証しない。

本体の型チェック、関連9単体テスト、通常client build成功（既存500KBチャンク警告）。通常buildは比較HTMLを配布対象に含めないため、比較入口自体の検証は上記ブラウザ実行による。サーバー変更なし。
