# 生存カード デザインプレビュー（2026-11-04、Claude Code）

生存カードを「見分けられる」「選びたくなる」「組み合わせたくなる」カードにするための見た目と操作表現の試作。独立したHTML/CSS/JSで、実ゲームのコード・CSS・カード定義・保存・通信は変更していない。カードの分類・性能・抽選・初期配布・融合・難易度は主担当が決める。ここでは決めていない。

## 起動手順

リポジトリのルートで次のどちらかを実行する。

```
node design/survival-card-preview/serve.mjs
```

ブラウザーで http://127.0.0.1:5190/design/survival-card-preview/ を開く。依存パッケージは不要。配信するのはこのフォルダと既存のカード画像（`public/rebuild/upgrades/`）だけ。

または `design/survival-card-preview/index.html` をChromeで直接開く（file://でも動く）。

左下の「表示」ボタンで次を切り替えられる。URLでも指定できる。

| 項目 | 内容 | URLでの指定 |
| --- | --- | --- |
| 場面 | 基地・デッキ編集 / プレイ中の3択 / 戦闘HUD / 一時停止の一覧 / 比較表 | `scene=base` / `run` / `hud` / `owned` / `compare` |
| 3択の例 | 開幕 / 段階アップ / 融合 / 属性の仮例 / 長い名前 / 選んだ直後 / 選択不可 | `case=opening` / `levelup` / `fusion` / `samples` / `long` / `picked` / `disabled` |
| 表示分類の仮割当 | 補強＝基礎・他＝デッキ / すべてデッキ / すべて基礎 | `kinds=family` / `deck` / `basic` |
| 動きを減らす | 動きを止めた表示 | `motion=reduce` |
| 基地のタブ | 強化 / 融合 / 仮例 | `tab=upgrades` / `fusions` / `samples` |

`ui=0` を付けると操作パネルを隠す（撮影用）。

カードの名前・説明・段階ごとの効果・3択の文面・解放条件は、現行ソースから書き出したもの（`cards-data.js`）。ソースが変わったら次を実行して作り直す。

```
node design/survival-card-preview/tools/build-data.mjs
```

撮影と検査は次で行う（`serve.mjs` の起動後）。

```
node design/survival-card-preview/tools/capture.mjs
```

## デザイン方針

現行の生存カードは、チェック付きの四角いタイルと、色帯だけの系統表示だった。同じカードが基地・3択・HUDで別の見た目になっていた。改修の方針は次のとおり。

1. **意味ごとに表現を分け、色だけに頼らない。**
   - 表示分類（仮）＝枠の形＋文字ラベル
     - 基礎：銀。右上の角が1つ欠けている。四角いラベル「基礎」
     - デッキ選択：青。対角の2角が欠けている。平行四辺形のラベル「デッキ」
     - 融合：金。二重線と四隅の金具。◆付きのラベル「融合」
   - 系統・属性＝丸い紋章＋絵柄の背景模様＋文字。爆発・貫通・迎撃・補強は現行データ。火炎・氷結・電撃・呪い・風は仮例。
   - 射撃方式＝角丸の四角いチップの矢印＋文字（分裂・後方・左右・分身。すべて仮例）
   - 段階＝丸。3択では、増える1つを中抜きの明るい丸で示す。
2. **同じカードはどの場面でも同じ部品で描く。** 大きさだけを変える。
   - L：3択
   - M：デッキ編集
   - row：取得一覧
   - S：HUD
3. **情報の順序はどのサイズでも同じ。** 状態（獲得の種類）→ 絵柄 → 系統・射撃方式 → 名前 → 段階 → 効果 → 素材。
4. **候補（デッキ）と取得を別の記号にする。**
   - 基地で候補に入れた状態：右端の四角いチェックと「候補」
   - 作戦中に取得した状態：丸い段階
   - 分類ラベル「デッキ」と同じ語を、チェックには使わない。
5. **動きは短い反応だけにする。**
   - 登場：240ms
   - 決定：260ms
   - 押下：90ms
   - 融合：注目したときに光が1回横切るだけ。
   - 常時の発光・粒子・揺れはない。現行にある融合の常時発光も使っていない。
   - OSの動きを減らす設定（`prefers-reduced-motion`）と、ゲームの `html[data-menu-reduced-motion="true"]` の両方で、すべての動きを止める。
6. **既存の画面構成は変えない。** 基地のヘッダー・デッキ欄・タブ・詳細欄、3択の見出し・「現在の強化」・再抽選、一時停止の構成はそのまま写し、カードだけを差し替えた。仮例タブはプレビュー専用。

## 場面と状態

| 場面 | サイズ | 状態 |
| --- | --- | --- |
| 基地・デッキ編集 | M（56px高、844幅で3列・640幅で2列） | 未選択 / 候補に入れた / 詳細表示中（金の縁） / 未解放（鍵＋解放条件） / 融合：未発見（？・斜線の枠） / 素材n/2 / 狙える |
| プレイ中の3択 | L（844幅で265×270px、640幅で203×262px） | 新規獲得（＋） / 段階アップ（↑） / 融合進化（◆、素材を表示） / 融合強化（◆） / 決定（スタンプ） / 選ばれなかった（薄く） / 選択不可（斜線＋理由、仮） |
| 3択中の「現在の強化」・一時停止 | row | 段階n/最大 / 最大段階（金の丸） / 融合（二重線） / 空き枠（点線） |
| 戦闘HUD | S（24px） | 段階の数字 / 最大はM（金地） / 融合は金の枠 / 空き枠 |

タッチ操作：
- デッキ編集では、カード本体を押すと詳細が出る。右端の全高×36〜40pxを押すと候補の出し入れになる。
- 未解放のカードを押すと、出し入れはせず解放条件を示す。
- 3択はカード全体が押せる。効果文はすべてカードの表面に出し、hoverに隠していない。
- 3択中も「現在の強化」から取得一覧を開ける。

## 部品構成（ゲームへ組み込むとき）

| ファイル | 役割 |
| --- | --- |
| `card.css` | カード部品。すべて `.sc-` 接頭辞。サイズ L/M/S/row、分類・系統・状態・動きの軽減を含む |
| `card.js` | `SurvivalCard.render.L/M/S/row(view, iconBase)` が文字列を返す純関数。`emptySlot("S"\|"row")` も同じ |
| `preview.css`・`preview.js` | プレビュー周辺（既存画面の写し・場面切替）。組み込みには使わない |
| `samples.js` | デザイン用の仮例 |
| `tools/` | データの書き出し・撮影検査 |

組み込みでは、`front-upgrade-ui.ts` の `frontUpgradeCardMarkup`（3択）、`frontUpgradeStrip`（HUD）、`frontUpgradeDetails` の `li`（取得一覧）を置き換える想定。基地は `front-base.ts` の `.base-tile` を `render.M` に置き換える想定。

既存の `data-card`・`data-pool`・`data-inspect` 属性と、役割（`role="checkbox"`、`aria-checked`）は維持してある。既存の操作処理・検証器のセレクターに合わせやすい。

組み込み時に、主担当が既存の検証器との整合を確認すること。例：`check-front-base.mjs` はチェック枠を20×20pxと判定している。

### 受け渡すデータ項目（CardView）

| 項目 | 型 | 内容 | 現行データでの出典 |
| --- | --- | --- | --- |
| `id` | string | カードID | `FrontUpgradeId` |
| `name` | string | カード名 | `FRONT_UPGRADE_CATALOG[id].name` |
| `kind` | `"basic"\|"deck"\|"fusion"` | 表示分類（仮）。枠の形を決める | 未定（主担当が決める。プレビューでは補強＝基礎・他＝デッキ・融合＝融合と仮に割り当てた） |
| `affinity` | `{key,label}` | 系統・属性。紋章と背景模様を決める | `family`（explosion/piercing/interception/generic）。属性（fire/ice/lightning/curse/wind）は未実装 |
| `shot` | `{key,label}` 任意 | 射撃方式（split/rear/sides/clone） | 未実装 |
| `art` | `{kind:"image"\|"atlas"\|"glyph", file, index}` | 絵柄 | 現行の `rebuild/upgrades/*.png` と `fusion-atlas.png`。切り出しは `front-upgrade-ui.ts` の `atlasIds` と同じ |
| `description` | string | 表に出す効果文 | 3択＝`frontUpgradeCardCopy().description`、一覧＝`frontUpgradeEffect(id, level)`、詳細＝段階1の効果 |
| `level` | `{current,next?,max}` | 段階。`next` があると増える1つを示す | `levels[id]`、`maxLevel` |
| `acquisition` | `"new"\|"level-up"\|"fusion-new"\|"fusion-up"` | 3択の獲得の種類 | `frontUpgradeCardCopy().intent`・`status` から対応付け |
| `materials` | CardView[] 任意 | 融合の素材 | `FRONT_FUSIONS[id]` |
| `deck` | `"in"\|"out"` 任意 | 基地での候補の出し入れ | `draft.pool.includes(id)` |
| `locked` | string 任意 | 未解放の理由 | `攻略${FRONT_CAMPAIGN_UNLOCKS.stage}クリアで解放` |
| `undiscovered` / `fusionProgress` | bool / string | 融合の未発見・素材の進み | `readFrontFusionDiscovery`、素材の候補数 |
| `inspecting` | bool | 詳細表示中 | 基地の `selected` |
| `state` | `"picked"\|"dismissed"\|"disabled"` 任意 | 3択の決定・非選択・選択不可 | 現行の `is-picked`・`is-dismissed`。選択不可は仮 |
| `reason` | string 任意 | 選択不可の理由 | 仮 |
| `sample` | bool | デザイン用の仮例 | 組み込み時は使わない |

## 確認結果

確認は2026-11-04に、Chrome（Playwright）で次の条件で行った。844×390・640×360の2サイズ × 動きの通常／軽減で、全126項目に合格した（`shots/report.txt`）。

- 横スクロールなし。カードは画面内に収まる。
- 3択の本文が欠けない。3枚が重ならない。下端が画面内に収まる。
- 候補チェックの当たり判定は最小36px。詳細を開く部分の高さは48〜52px。
- 一度に全体が見えるカードの数：844幅で9枚、640幅で6枚（現行と同等）。
- 動きを減らす設定では、3択のアニメーションがnoneになる。
- 通常時は、登場（sc-enter）と決定（sc-pick）の短い動きだけ。
- 融合を含む3択で、0.8秒後に動き続けるアニメーションは0件。
- 操作：
  - 候補の出し入れができる。
  - 詳細を切り替えられる。
  - 未解放のカードは出し入れせず、解放条件を表示する。
  - 3択で選ぶと「決定」と「選ばれなかった」の表示になる。
  - 3択中に「現在の強化」を開ける。
- ページ例外は0件。
- `index.html` を直接開いた場合も全場面が表示され、画像の欠けは0件。

画像は `shots/` にある（`{幅}x{高}-{場面}.png`、`-reduce` は動きを減らす設定、`compare-844.png` は比較表の全体）。

実スマホでの見え方・押しやすさ、実ゲームへ組み込んだときの表示は未確認。

## 仮の仕様・未確認事項

- 表示分類（基礎・デッキ・融合）は仮。正式な区分・出現ルール・名称は主担当が決める。枠の色・形は強さの等級ではない。
- どのカードを基礎とするかは未定。プレビューでは補強系を基礎に仮で割り当て、切り替えられるようにした。
- 属性（火炎・氷結・電撃・呪い・風）、射撃方式（分裂・後方・左右・分身）、仮例カードの名前・説明・段階数は、すべてデザイン用の仮置き。数値・対象・発動条件・初期枚数は決めていない。
- 選択不可の3択カードは、現行のゲームでは出ない状態の表示例。必要かどうかは主担当の仕様次第。
- 「候補」という語は現行の画面のまま。「デッキ」に統一するかは主担当の判断。
- 仮例の絵柄はSVGの紋章。正式な属性カードの絵柄（画像）は未制作。
- HUDの24pxでは枠の形の差が小さい。融合（金）以外の区別は、名前・段階を読み上げ用ラベルに持たせている。実機で見分けられるかは未確認。
- 既存カードの画像には1〜2MBのものがある（例：`emergency-armor.png`）。カード表示が増えると読み込みが重くなる可能性がある（未計測）。
