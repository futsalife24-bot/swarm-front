## 開き方

ESモジュールを使っているので、`file://` で直接開くと動きません。静的サーバー経由で開いてください。

- **プレビュー**：`design/resume-ui-20261110/` を静的配信して `preview.html` を開きます。`?check=1` を付けると配置の検査関数 `__check()` を読み込みます。
- **自動検証**（rootで実行。既存の `node_modules` の playwright と sharp を使います。新しい依存の追加はありません）：

```bash
node design/resume-ui-20261110/verification/run-verify.mjs --old task-pleat-lightweight/prototypes/gacha-reveal
```

この検証は、127.0.0.1 の空きポートで内部サーバーを起動し、インストール済みの Chrome で実行して、終わると止めます。外部への送信はしません。`--no-shots` を付けると画像を作りません。

## モジュールの使い方

```js
import { createSupplyReveal } from './supply-reveal/supply-reveal.js';
// CSS は supply-reveal/supply-reveal.css を読み込む
const reveal = createSupplyReveal(document.body, {
  label: '配布券（仮）',        // HUDの表示名
  reduced: undefined,           // 省略時は prefers-reduced-motion に従う
  fast: false,                  // 2倍速
  storage: sessionStorage,      // 中断・再開用（null で無効）
  pendingKey: 'supply-reveal-pending',
  finalActions: [{ id: 'close', label: '閉じる', primary: true }], // 'again' を入れると「同じ結果でもう一度」
  onAction: (id) => {}, onClose: () => {}, onEvent: (e) => {},     // e.type: play / stop / final / option
});
reveal.play([{ type: 'weapon', rarity: 'SSR', name: '狙撃銃（仮）', new: true }]); // 1件または10件
```

- **入力**：`type` は `weapon`／`shard`／`buddy`。`rarity` は N／R／SR／SSR で、LR は受け付けません。`shard` は `amount` を持ちます。`new:true` の時だけ NEW と「新しいバディが合流」を表示します。
- **主なメソッド**：
  - 再生・操作：`play(results, {atEnd})`、`replay()`、`tap()`、`skip()`、`close()`、`destroy()`
  - 設定：`setFast(bool)`、`setReduced(bool)`
  - 検証用：`seek(t)`、`simulate(seconds, fps)`、`state()`、`perf()`、`ticksByGen()`
- **純粋関数の書き出し**：`validate`、`build`、`frameState`、`omenLevel`、`audit`、`readPending`、`PRESETS1`、`PRESETS10`。プリセットは確認用の仮の結果です。
- **重ね順と安全領域**：`.sr-root` は `position:fixed; z-index:50` です。安全領域は `env(safe-area-inset-*)` を使っています。
- **確認用の窓口**：プレビュー側では `window.SupplyRevealPreview` に置いています。

## 旧試作から継承したもの

- **時間軸の設計**：時刻 t だけで1コマが決まる `build()` → `frameState()` → `apply()` の構成。
- **予兆**：下限だけを示し、紫 → 金 → バディの順に上がるだけ。結果の最高段階は超えません。

- **画面**：入口の画面構成、テーマ色、段階色。

## 変えたこと（見た目と演出）

- **ポッド**：
  - CSSの箱を、生成素材に置き換えました。
  - 落下時は噴射跡を付け、着地の影は高さに応じて変わります。着地すると砂ぼこりの輪が広がります。1連のときは着地パッドを置きます。
  - 開封では、蓋が継ぎ目を軸に跳ね上がり、開封口から光が漏れます。カードは開封口の中から持ち上がり、継ぎ目より下はポッドが消えるまで隠します。
  - 10連では蓋の動きを小さくし、隣のポッドに重ならないようにしました。
- **予兆**：
  - 1連は、ポッドの灯・継ぎ目の漏れ光・足元の光を下限の色にします。
  - 10連は、残ったSR以上だけ前面パネルに「SR以上」を出し、灯を紫にします。
  - 1連の予兆の表示（「SSR以上の反応」など）は、開封した時点で消します。
- **カード**：
  - 裏面は、斜めの柄・菱形の紋章・「SUPPLY」の表記。
  - 表面は、段階色の上部グラデーション・角の括弧・SR以上の光彩・表面を走る光。
  - 1連は、確定したカードを14%大きく持ち上げます。
- **カットイン**：薄暗い背景を敷き、流れる縦線と、背景の大きな輪郭文字（SSR／BUDDY）を追加しました。SSRの文字は金のグラデーションにしています。
- **HUD**：「SUPPLY DROP」の表記と、状況の表示を追加しました。状況は 降下中 → 解析中／反応を検知 → 開封 → 確定 → 受領一覧／受領完了 と変わります。状況の表示は、結果を先に漏らしません。
- **背景**：画像を使わない投下場にしました（壁・遠近の床の格子・霧）。上下に細い区切り線を入れています。
- **一覧**：
  - 見出しを「結果」から「受領一覧」に変えました。
  - 武装片は、名前に数量（例「武装片 ×20」）、種別に「素材」を出し、チップとの重複をなくしました。
  - 名前は枠の中で縦中央に置き、SSR・バディのタイルは光らせます。
- **光の上限**：白の一瞬の光の上限を 0.6 から 0.45 に下げました。点滅はしません。
- **テンポ**：降下を 0.38秒 から 0.42秒 にしました（弾みを読めるようにするため）。全体は0.04秒長くなります。

## 検証（2026-11-10、このPC、Google Chrome 156.0.8078.81 を Playwright で操作）

- **予兆と停止点の検査**：全13プリセット×通常／動き減の26通りを、1/60秒刻みで検査し、26/26合格。
  - 検査項目：予兆が結果を超えない、ランプが結果を超えない、開封前に表を見せない、SR未満に「SR以上」を付けない、SSR未満にカットインしない、`new:false` に NEW を出さない（カード・カットインとも）、停止点でカットインが完成している、最後に全件が表になる。
- **配置**：844×390、640×360、568×320 で、通常は各50場面、動き減は各26場面。計228場面すべてで、次の4点が0件でした。
  - 画面外
  - 44px未満の操作（高さ）
  - 文字の切れ・はみ出し（カードの名前、一覧タイル、カットイン名、HUD、状況表示）
  - 重なり（操作どうし、文字×ボタン、タイル内）
  - 対象の場面：入口、1連7種の降下・予兆・開封・最後、10連3種の降下・予兆・一斉開封・個別開封・各停止点・一覧。
- **演出中のスキップ**：入口の「10回使う」を実際にクリックし、0.93秒後（降下中）に「スキップ」（80×44、有効）をクリックしました。最後（11.03秒）へ移り、一覧が表示されました。

- **停止点（実時間）**：実時間で再生し、最初の停止点7.07秒で止まりました。
  - 止まった直後に8回クリックしても止まったまま。
  - クリックせずに2秒待っても止まったまま。
  - 0.5秒以上たってからのクリックで次へ進みました。
- **停止点（固定刻み）**：1倍・2倍とも、7.07秒・9.77秒・11.03秒のすべてで、その時刻ちょうどに止まりました。止まっている間に3秒分進めても動きませんでした。

- **中断と再開**：再生中に再読み込みすると、入口に案内が出ました。「結果を見る」で10件の一覧が最後の状態で表示され、保存は消えました。
- **動き減の途中切替**：結果の並びは同じまま、動き減で続きました。
- **描画の負荷**：
