# 兵士の連続動作・固定入力による確認

これはゲームの `step()`、`Renderer`、兵士GLBと武器GLBを使った開発用の検証場面です。通常ソロ出撃での新モデル表示・武器切替の確認を補い、連続した動作と遷移を近距離で確認するために作成しました。

- 通常速度 `normal.mp4`: 24fps、38秒、912コマ。実時間の録画ではなく、描画の進行を1/24秒ずつ進めて全コマを保存した映像。PCの実プレイ性能を示す映像ではありません。
- 半速 `half-speed.mp4`: 同じコマを時間方向に2倍へ拡大。中間姿勢の生成や補間映像による補完はしていません。
- `contact.jpg`: 24時点の姿勢の抜粋。これだけで全遷移を検証済みとは扱いません。
- `metrics-summary.json`: 元のゲーム状態から弾数減少、装填、持ち替え、回避、ジャンプ、転倒、識別スロットを確認。

## 範囲と限界

ゲームの物理更新は通常ソロと同じ20Hz。描画側は24fps固定です。4人の状態を進め、注目する1人だけを描画。現行のマップと兵士の描画・補間処理を使用しますが、敵と影は無効、カメラは確認用の近距離位置、構え入力は有効です。保存データにはアクセスしません。対人同期・通信遅延・全地形・全34クリップの全組み合わせ・実プレイのフレームレートを証明するものではありません。

動作の順序: 0秒待機、2秒歩行、5秒走行、8秒射撃、10秒装填、14秒移動射撃、16秒移動装填、20秒持ち替え、23秒元の武器へ、26秒踏み込み回避、28秒後退、29.5秒横移動、31秒ジャンプ、34秒被弾・転倒。各開始と終了を含む連続コマです。

ユーザーが承認した低い踏み込み回避と一瞬の武器床貫通を不合格理由にしません。体・手・関節の自然さは確認対象に残します。3種類の各姿勢の抜粋を自己レビューし、銃の取り付け方向と装填時の腕、持ち替え、回避の姿勢を確認しました。独立監査の合格を意味しません。

## 再現

1. `node node_modules/vite/bin/vite.js --config vite.soldier-review.config.ts`
2. Chromeで `http://127.0.0.1:5198/soldier-integration-review.html?v=20261009-proof3` を開く。
3. 武器を選び「連続動作を保存」。読み込み完了後に912コマを `test-results/soldier-capture/<武器番号>-<時刻>/` へ保存。
4. `python scripts/summarize-soldier-capture.py <コマのディレクトリ> <出力先>` で欠落と動作イベントを確認。
5. `ffmpeg -framerate 24 -i <コマのディレクトリ>/%04d.jpg -c:v libx264 -crf 23 -pix_fmt yuv420p -movflags +faststart <出力先>/normal.mp4`
6. `ffmpeg -i <出力先>/normal.mp4 -vf setpts=2*PTS -r 24 -c:v libx264 -crf 23 -pix_fmt yuv420p <出力先>/half-speed.mp4`

保存先は開発用の固定ディレクトリのみ。専用Vite設定は127.0.0.1:5198からの同一OriginのPOSTだけを受け付け、番号と時刻とファイル名、件数、リクエスト容量を制限し、既存ファイルは上書きしません。本番のビルド入口・Workerには含めません。

兵士GLB SHA256: `bea4886cd676e602816df15de52424dc953279d0b463de61ba9860c3bfef280e`。識別色は `495960b77d04bae38e51a42d96b8194a12a0ccf0` の固定スロット修正を使用。モデルID・推論設定は未確認。
